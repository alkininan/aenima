Build

1. Guard hook — PreToolUse, project scope (.claude/settings.json, committed).
   scripts/hooks/guard.mjs (Node, no new dependency), reads the hook JSON on stdin and
   exits 2 with a one-line reason on stderr when the call matches any of:
   a. Bash command containing `db:push` or `drizzle-kit push` — always.
   b. Bash command containing `db:migrate` — always, for now. Migrations are applied by a
      human until T0.8 adds the Decision-answered path. Reason text names T0.8.
   c. Bash command containing `vercel` together with `--prod` or `deploy`.
   d. Bash command containing `git push` with `--force` or `-f`, or `git merge` while the
      current branch is main. Normal `git push` stays allowed — direct-to-main blocking
      arrives with T0.8 when tickets move to branches.
   e. Edit, Write, or a Bash redirect targeting any path matching `.env*`.
   Matchers: one group for Bash, one for Edit|Write. Reason text is law-6 language:
   what was refused and where the rule lives, never "violation".

2. Gate hook — Stop, project scope. scripts/hooks/gate.mjs runs
   `pnpm lint && pnpm typecheck && pnpm test` from $CLAUDE_PROJECT_DIR. Green → exit 0.
   Red → exit 2, stderr = the last 40 lines of the failing command's output.
   Loop guard: read `stop_hook_active` from stdin; keep a counter in
   .claude/.gate-count (gitignored) and after the third red in one session exit 0 with
   "gate released after three attempts — see the three-failed-corrections rule" so a
   session can never spin forever. Hook `timeout` long enough for the db tests; measure
   `pnpm test` once and set it to 2× that.

Rules
- Deterministic checks are hooks, never sentences in a prompt.
- The reviewer never edits. Bash is for diff and tests only.
- Do not commit .claude/.gate-count or anything under .env*.
- Where the spec or these docs are silent, stop and list the question. Never assume.

Criteria → Tests, each observed once
- AC1 A session with a red test cannot end → TC1 make one test red, try to finish,
  observe the gate refuse, fix, observe it release.
- AC2 `pnpm db:push` and `pnpm db:migrate` are refused → TC2 attempt each via Bash,
  observe the refusal text.
- AC3 An Edit on .env.local is refused → TC3 attempt it.
- AC4 The reviewer finds a planted defect from a fresh context → TC4 on a scratch
  branch, plant an off-by-one in a pure function with its test left green, invoke the
  reviewer, observe the finding, delete the branch.
- AC5 A worktree session sees .env.local → TC5 `git worktree add /tmp/wt-check` and
  confirm the file is present, then remove it.

Done means
  pnpm lint && pnpm typecheck && pnpm test
  each of TC1–TC5 observed and quoted in the report
Then the cold review: invoke the reviewer subagent on this ticket's own diff. Fix every
finding it raises, re-invoke until PASS or list the findings you disagree with and why.
