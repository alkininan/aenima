## Objective

The sign-in flow and every form follow design-spec v2.21. What changed since they were built:
icon-button padding is (box − icon) ÷ 2; the floated label at rest is ui-label scaled 17/13 and
animates `transform` only; a field reserves helper lines for its longest message, two under the
OTP group; a submit is never disabled for an incomplete form; the resend keeps its label readable
with the time in a mono span; and a multi-step step has its column and mark geometry. The composer
is T3.2's.

### design-spec §7

## 7. Interaction states (any interactive element)

| State | Treatment |
|---|---|
| Hover | `--hover-overlay` + cursor pointer; on glass, border brightens to `--glass-border-hover`; primary adds a one-pass sweep (§8.1) |
| Active/pressed | press physics above + `--press-overlay` (the primary takes §6's `--bg-base` tint instead) — squish 0.985 + spring release |
| Focus-visible | prime ring + glow (keyboard only — pointer focus changes the border alone, per §6) |
| Selected | `--prime-soft` fill, `--n-primary` text |
| Disabled | `--n-disabled` text/icon, fills at 40% opacity, no hover, cursor default, edge highlight off (the resend cooldown keeps its label readable — §8.4) |
| Loading | element-level spinner (below) or skeleton; never full-page spinners |
| Drag | scale 1.02 + `--shadow-float` |
| Open (a trigger whose panel is open) | the trigger is hidden inside the panel's footprint (§6 Morph); focus lands on the panel's first item — a select's selected option, a combobox's input — and returns to the trigger on close |

**Hit areas.** The floor — 40 on pointer devices, 44 on touch (§4) — is a rule about what a finger or a pointer can hit, not about how large a control draws. A control whose box is smaller than the floor keeps its size and extends its hit area to the floor with a transparent `::before`, centred on the box, on whichever axis falls short: sm and md buttons, chips, tabs, the toggle, the checkbox and radio, the drag handle, the sortable-header chevron, the copy button. Where such controls sit closer together than the extension — a chip row — the hit areas overlap and the later element in document order takes the tap; a free-standing destructive control keeps 8 clear around its hit area, so nothing overlaps it. **Menu and option rows are their own hit areas:** 36 on pointer, flush to their neighbours and exempt from the 40 floor — rows stacked flush have nowhere to extend into; 44 on touch, where the row grows for real and the panel's height is what changes. A destructive row is the last in its panel, beneath a separator that carries 6 above and below it — that block is its clearance.

**Input and gestures — pointer and touch.** One table so no interaction is decided in a component. Pointer rules are gated by `@media (hover: hover) and (pointer: fine)`; touch is everything else, at any width — an iPad in hand chrome is touch, a narrow desktop window in hand chrome is pointer.

| Input | Pointer | Touch |
|---|---|---|
| Hover | `--hover-overlay`, border brightening, the primary's sweep, the overflow trigger brightening, the drag handle and row checkbox appearing in their reserved slot, tooltips after `--delay-tooltip` | Does not exist. Nothing is revealed by hover alone: the overflow trigger, drag handle and row checkbox are always rendered on touch |
| Click / tap | Fires on release; press physics from down to up | The same. `touch-action: manipulation`, so no double-tap zoom on controls and no tap delay |
| Press and hold | Nothing — there is no long-press on pointer | Nothing, except the drag handle: hold `--hold-lift` lifts the row (§8.28). No other long-press exists, so nothing hides behind one |
| Double-click / double-tap | Nothing. No inline editing anywhere (§16) | Nothing; zoom stays available on content, never on chrome |
| Right-click | The browser's own context menu, untouched; aenima's menus open only from visible triggers | Not applicable |
| Modifier-click | On a row, where the name is the link and covers the row (§8.27), modifier clicks belong to the browser — `Cmd/Ctrl`-click opens a new tab, `Shift`-click a new window. Range selection is `Shift`-click on a checkbox (§8.27) | Not applicable |
| Scroll | Sticky topbar and selection bar hold; the transcript follows a stream only while at the bottom (§8.34) | The same, with native momentum; a bottom sheet scrolls inside itself and never the page behind it |
| Swipe | — | Exactly one: dragging a bottom sheet's grabber down 80 or more, or releasing it downward faster than 0.5 px/ms, dismisses it (§8.21). No swipe actions on rows (§16) |
| Pinch | — | Allowed on content, blocked on chrome |
| Drag | The drag handle only (§8.28): scale 1.02 and `--shadow-float`, auto-scroll within 48 of a list edge | The same, after the `--hold-lift` lift |
| Text selection | Prose and readouts select; controls, rows and chips are `user-select: none` | The same |
| Multi-select | Row checkbox; `Shift`-click on a checkbox selects a range; `Cmd/Ctrl+A` selects every rendered row of the focused list | Row checkbox, always visible; no modifiers |
| Keyboard | §11 in full; roving focus in menus and lists | An attached keyboard gets §11 in full, and the modality script treats it as keyboard |
| Resize / rotate | The dock re-places itself per §4's modes; every open panel closes on a width change and when the docked dock opens or closes (§6) | Rotation is a width change; a height-only change (the browser's toolbar, the keyboard) closes nothing (§6) |
| Focus | Pointer changes a field's border alone; keyboard gets the ring (§6) | A tap focuses without a ring; a focused field scrolls into view above the software keyboard |

### design-spec §8.1

### 8.1 Buttons

All pills. Sizes: **sm** 28h, pad 5/10, gap 4, icon 18, ui-button-sm · **md** 34h, pad 7/14, gap 4, icon 20, ui-button · **lg** 48h, pad 14/20, gap 4, icon 24, ui-button. All `--r-pill`. **Height governs and the vertical padding derives from it**, per the option-row rule — each is (height − the label's line box) ÷ 2, so 28 − 18 gives 5, 34 − 20 gives 7, 48 − 20 gives 14. Retune a size by moving the height and recomputing the padding, never by moving the height to match a padding that has gone stale. Variants:
- **Primary:** `--grad-primary` fill, label `var(--bg-base)`, 1px `--edge-highlight` top specular. The light-fill/dark-label pairing is deliberate retro grammar. Hover lightens with `--hover-overlay` and runs a single left-to-right specular sweep — `--sweep`, `--t-sweep`, `--ease`, one pass per hover-in, none under `prefers-reduced-motion` and none on a disabled or loading primary. Press darkens with §6's `--bg-base` tint and applies the press physics. **The gloss is the primary's alone:** danger and every other variant stay flat.
- **Soft:** `--prime-soft` fill, `--prime` label.
- **Neutral:** `--surface-2` fill, `--n-primary` label. For chrome that must stay visible without reading as an accent.
- **Secondary:** transparent, 1px `--glass-border`, `--n-primary` label; hover brightens border.
- **Ghost:** text-only, `--n-secondary` → `--n-primary` on hover.
- **Danger:** `--danger-deep` fill, white label; destructive actions always get a confirm step.
States: hover overlay · press physics · loading (spinner replaces label, width locked) · disabled. **Icon buttons:** 28/34/48 square, icon 18/20/24, padding (box − icon) ÷ 2 = 5/7/12, same radius and variants.

### design-spec §8.2

### 8.2 Inputs

Field 48h, `--r-pill`, `--surface-1` fill overlaid with `--sheen` beneath the top specular, 1px `--glass-border`, pad 16 horizontal (height wins: the value centres vertically, per §8.5's height-wins rule), icon slots 24 leading/trailing, gap 8, ui-input text. 48 aligns fields with the lg button, so a field and its submit sit at one height. Focus: pointer → `--prime` border only; keyboard modality (§6) → border + ring + glow. Error: `--danger` border. **Error outranks focus:** a focused field in error keeps the `--danger` border and icon; keyboard modality still adds the `--prime` ring outside it, and pointer focus on an errored field shows only the caret and the floated label. Disabled: 40% opacity. **The leading icon takes the field's state colour** — `--prime` on focus, `--danger` on error, `--n-secondary` otherwise, `--n-disabled` when disabled. The icon is part of the field's state, not decoration beside it; a field that signals only at its border makes the user hunt for what changed. **No `backdrop-filter` on a field:** the sheen is a material, not a layer, and blur belongs to the glass recipe's surfaces alone (§5).
**Floating label.** The label is a real `<label>`, always in the DOM, never a placeholder. At rest (empty, unfocused) it renders inside the field where the value will sit — at input size, `--n-secondary` (AA), not placeholder tone. The at-rest label sits inside the pill's 1px border, so its rest offset is 9 (41 behind a leading icon): label and value paint at the same x, and the border is part of the geometry, not a rounding error. On focus or once filled, it floats to the label zone above the field: ui-label (§3), `--n-secondary`, 6 above the field, left-aligned 8 from the field's left edge, in a label zone with 8 side padding — the label hugs the container edge regardless of leading icons; only the value moves for an icon. **The label floats on `transform` alone:** at rest the label is its floated self — ui-label — scaled by 17/13 from its top-left and translated into the field, so it reads at input size; the float animates `transform` only, over `--t-fast` on `--ease`, never `font-size`, which would re-lay the text out on every frame. At rest it is therefore Medium, a touch heavier than a typed value, which at `--n-secondary` is imperceptible. `prefers-reduced-motion` snaps it. The label zone (24h = 18 line + 6 gap) is **always reserved**, so floating never shifts layout. A field shows one text, ever: its label. Format-hint placeholders are abolished — after the label floats, the field is empty with a caret. Nothing swaps, nothing appears. **Exempt from the floating label:** Search (the leading icon names it; placeholder "Search" allowed at rest) and the chat composer (the dock names it; placeholder "Message aenima", §12) — both are labelled by context, not by a `<label>` row. `--n-placeholder` exists only for these two.
**Helper line speaks only in states.** The helper slot (ui-footnote, 8 below the field) carries validation outcomes exclusively — error `--danger`, warning `--warning`, success `--success` — never instructions; instructional copy lives in the subtitle slot (§4). **A field's helper line carries only errors about that field's own value.** A failure belonging to a control elsewhere on the step surfaces at that control, never on the nearest field; **a request-level message** — a rate limit, a send that failed — renders in one slot under the step's last control, ui-footnote `--n-secondary`, centred, wrapping (§8.10's precedent). **A field reserves as many helper lines as its longest message needs at 343 wide in the longest locale** — one (18h) under an ordinary field, two (36h) under the OTP group, whose wrong-code string measures 305 at 343 and crosses onto a second line under §12's +30% reserve — so an error appearing never shifts layout, and a message never truncates. **Validation timing — flag slow, clear fast.** Before submit a field never errors while empty or under 3 characters, blur included: leaving an untouched field is not a mistake. While typing, validation waits for a 1.5s pause; blur validates immediately once the field carries ≥3 characters. Submit validates everything, empty fields too, and scrolls to the first error; a submit is never disabled for an incomplete form — pressing it is how the person learns what is missing. The moment input becomes valid, the error clears instantly — flagging waits, clearing never does.
**Autofill paint.** Browser autofill (Chrome's yellow/white flash) is overridden as law, not left to chance: `input:-webkit-autofill { -webkit-box-shadow: inset 0 0 0 1000px var(--surface-1); -webkit-text-fill-color: var(--n-primary); caret-color: var(--prime); transition: background-color 9999s; }` — the field must look identical filled by hand or by the browser.
**Textarea/composer:** starts as the 48h pill and grows with its content by the line — 22 a line on 13 of vertical padding, so 70 at two lines and 92 at three — taking §5's proportional radius from the third line (92h → r23) and stopping at eight lines, 202h, where it scrolls inside. **Search:** leading icon variant of the standard field. **Date field:** standard pill field + native browser picker (custom calendar is v1.1). **OTP:** 6 boxes, special-otp centered, filled box border `--prime` — a distinct component with its own geometry, deliberately exempt from the 48 field height. **Two sizes:** ≥768 **52×52**, gap 16 · <768 **44×44**, gap 8; both `--r-pill`, which clamps to half the box. Six 52s and five 16s span 392 and overflow a 375 phone; the small scale spans 304 and fits, and meets §4's 44 touch floor exactly. The label is `sr-only` at both sizes: the step title ("Enter your code") is the visible name, and a label row beneath it would say the same thing twice. Note for implementers: the focus ring (2px at 2px offset, §6) reaches 4 into the small gap of 8 — clearance is tight but rings never touch. **Mechanics:** one logical input behind six boxes, `inputmode="numeric"`, `autocomplete="one-time-code"`; a paste fills every box; Backspace steps back one box; the sixth digit submits as a pending move (§8.34), so the primary is a second path to the same submit; a wrong code keeps the digits, turns all six borders `--danger` and selects them, so the next keystroke replaces the code whole.

### design-spec §8.3

### 8.3 Multi-step flows

Sign-in, onboarding, ceremony steps. **Geometry:** the step is a centred column of 400 (§8.21's and §8.24's bound), the mode's gutters outside it; the Æ mark 32 (§1's header size) is centered above every step, 48 below the top of the page — 16 below 600 tall (§4 Height); 24 from the mark to the title block; 24 from the title block to the first label zone; field blocks stack with no further gap, since the reserved helper lines and the next label zone are the space; 8 from the primary to the tertiary. The step title is display-lg (§3) and its subtitle is the §4 subtitle slot. A step with no back button centers its title and subtitle beneath the mark. A step with a back button uses the header grammar instead: a row of back control then title, with the subtitle under the title — title and subtitle left-aligned to each other, never centered beside a back control. The back is an IconButton, neutral variant (visible `--surface-2` circular fill at rest — ghost disappears in a header), 48, `arrow-left` 24, gap 12 to the title block. Back always means "previous step" and replaces textual escape hatches that mean the same thing ("Use a different email" is the back button). Controls follow, then the primary lg filling the column; tertiary actions ("Send a new code") beneath it, centered, Neutral md, maximum one per step. **Back and the tertiary use the same variant:** they are the same tier of chrome on the same step and must read as one family. Ghost is wrong for a tertiary that can be disabled and counting down — it vanishes precisely when it has the most to say. The OTP group stays centered (six discrete boxes are a display, not a text field). Step changes are instant — no slide transitions in v1, and the same holds for every route change in the product (§6): a route cross-fade would be a document view transition, which is the morph's one slot and would stall a streaming dock.

### design-spec §8.4

### 8.4 Resend cooldown

A tertiary resend action ("Send a new code") is disabled for 60s after a code is sent and counts down in its own label — "Send a new code (0:47)" — returning to its normal label at zero. The cooldown starts when a code is sent, not when the resend is pressed: arriving at a code step means one has just gone out, so the resend opens already counting down. The provider's window belongs to the address, not to the control, and a resend that is live on arrival hands the user exactly the rate-limited tap the cooldown exists to prevent. The cooldown is the mechanism, not advice: without it a second tap hits the provider's rate limit and the failure lands on whatever field is on screen, which blames the user for a control the product left enabled. A control that cannot succeed for a reason the person cannot fix — a cooldown, a request in flight — is disabled, never merely apologised for. **While it counts down the control is disabled in behaviour** — no hover, no press, cursor default, fill at 40% — **but its label stays `--n-secondary`** and the time is a mono-readout span inside it, so the one changing thing on the step is readable and its width holds still: §13's disabled exemption is for controls that carry no information, and this one carries the only information on the step.

### design-spec §17 (the six checks this ticket covers)

## 17. Conformance

What a ticket that cites this document is checked against. Each line is one assertion, and the check that proves it is in the parentheses: *grep* runs over the repository, *dom* is a component test in the existing suite, *browser* is the same test run in a real engine (Playwright, or the suite's browser mode) — every check that measures layout, media queries, hit-testing, the top layer or transitions is *browser*, never *dom*, because a DOM emulator has no layout and passes those vacuously — *script* is a small program over this file and the stylesheet, *eye* is the kitchen-sink route looked at. The kitchen-sink route takes `data-force-fallback`, which forces the JS positioner, the bare open without `startViewTransition` and the solid `--glass-fallback` recipe, so both placement paths, both transition paths and both glass paths run in one engine. A ticket's Tests name the checks they cover by id; a check no ticket covers is a gap in the ticket, not in the check.

- C-07 Buttons are 28, 34 and 48 tall with vertical padding (height − line) ÷ 2, and icon buttons are square at the same three (browser).
- C-08 A field is 48 tall with its 24 label zone and its reserved helper lines: nothing moves when the label floats or an error appears, the two-line OTP helper included (browser, bounding boxes before and after).
- C-18 A field shows no error while empty or under 3 characters, including on blur; while typing it waits 1.5s; a valid value clears the error at once; submit validates everything, empty fields included, and scrolls to the first error (dom, fake timers).
- C-19 The resend opens disabled and counting down from the moment a code is sent, in the shape "Send a new code (0:47)" with the time in a mono-readout span and the label in `--n-secondary`, and returns to its label at zero (dom).
- C-27 No input has a font size below 16 at any width, every control carries `touch-action: manipulation`, and the tap highlight is transparent (grep and browser).
- C-31 The focus ring appears only after keyboard modality; a clicked field changes its border alone; a page-focused field carries no ring on load; the main region never carries one (browser).
