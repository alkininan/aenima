1. `/run` — one file in the repo, the protocol below as its body. Every deterministic
   step is a script under scripts/run/ (Node, no new dependency) that the skill calls;
   the skill holds judgment only. Steps, in order:

   0 Preflight
     a. Decision assessment. For each task at Decision: read comments; the pipeline's
        own are the ones starting with the prefix, yours are the rest. A human comment
        newer than the last prefixed one gets exactly one assessment: resolves the
        question with one interpretation → set Ready; if Where named a spec section,
        note the patch as the first act after claim. Does not resolve → one prefixed
        clarifying comment; count clarifying comments on that question, and after two,
        post nothing more — read only. Never set Ready without a resolving comment.
     b. Merge detection. For each task at Review: if its Commit is an ancestor of
        origin/main (git merge-base --is-ancestor) → set Done. If any became Done and
        origin/main advanced past the newest Releases row, create one Releases row:
        Name "YYYY-MM-DD <short>", Commit, Date, Deploy https://aeni.ma, Tasks = the
        newly Done, Specs = the four header versions at that commit.
     c. If any task is In progress: stop, report "a run is in progress: <name>", exit.
        No claim. Stale detection is T0.9's.
