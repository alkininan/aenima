## Findings

**1. Must — `claims.mjs` reports names `origin/main` has, which is the half of AC1 that says
"and none that it has".**

`scripts/run/claims.mjs:161`:

    file: (name) => g(["cat-file", "-e", `${ref}:${name}`]).status === 0,

A token is looked up as a path relative to the repository root and nowhere else, so every
backticked bare file name in a ticket — the way this repo's tickets usually name a script —
comes back absent although main holds the file one directory down. Measured over all 36 files in
`docs/tickets/`: 51 `absent` entries, of which at least 41 name a file `origin/main` tracks.
`docs/tickets/T0.32.md` reports `log-index.mjs` and `version-drift.mjs`, both of which are
`scripts/run/log-index.mjs` and `scripts/run/version-drift.mjs` on main. `docs/tickets/T1.4.md`
reports `OpportunityHeader.tsx`, `ItemLine.tsx`, `item-key.db.test.ts` and `item.test.ts`, all
four of which main tracks under `src/`. `docs/tickets/T0.97.md` reports five in a row —
`stale.mjs`, `claim.mjs`, `release.mjs`, `review-scope.mjs`, `report-check.mjs` — and every one
of them is in `scripts/run/`.

This is not noise around the edge of the signal, it is four fifths of the output, and it
contradicts the dichotomy the skill hands the run at `.claude/skills/ticket/SKILL.md:303-306`:
"Each is either something this ticket creates — the common case, and nothing to do — or drift: a
file that moved, a function that was renamed." `log-index.mjs` is neither. A run that reads step
2's list finds forty names it must adjudicate by hand and one that matters, which is the shape
the Objective set out to remove.

`classify` at `:111-113` already knows the token is a file name; what is missing is the lookup
for one. Smallest correction: in `gitLook`, read the reference's tracked paths once
(`git ls-tree -r --name-only <ref>`, the call at `:157` widened or a second one beside it), keep
the last segment of each in a Set, and let `file` answer true when `cat-file -e` misses but some
tracked path's last segment equals the token. One TC1 case reddens it: a fixture naming a file
that exists under a directory, asserted out of `absent`.

I am confident about the behaviour — it is measured — and less confident that you read AC1 the
way I do, since "a path `origin/main` lacks" can be read as root-relative. Tagged Must because
the consequence is the same either way: the list step 2 hands the skill is mostly false, and
nothing in the ticket or the tests records that as intended.

## Shoulds

These are recorded and do not block.

1. **An unreadable reference reports as a repository with nothing in it.** `claims.mjs:157-163`:
   when `git ls-tree` fails, `tops` becomes `[]` and every `cat-file`/`grep` fails with it, so a
   worktree whose `origin/main` is unfetched gets every name in the ticket returned as `absent`
   with no signal that nothing was read. `docs/guidelines.md` §5 sets the opposite precedent for
   the harness — "When `origin/main` cannot be read the guard refuses everything and the gate
   refuses to close, each saying so" — and `cli.mjs`'s `emit({ error: … })`, which this file
   already uses at `:176`, is the shape for it. Emitting an `error` when the `ls-tree` at `:157`
   fails would close it.

2. **The identifier lookup is a substring grep over every tracked file, `docs/` included.**
   `claims.mjs:162` runs `git grep --quiet --fixed-strings -e <name> <ref>`. Without `-w` a
   fragment answers for the whole: `git grep -F -e unScorer origin/main` succeeds. And because
   the search covers `docs/`, a name survives in `docs/build-log.md`, `docs/reviews/*` or an old
   ticket pack long after the code dropped it — `next_scoring_attempt_at` is found in
   `CLAUDE.md`, `docs/build-log.md`, `docs/log/T2.4.md`, `docs/reports/T1.5.md` and
   `docs/reviews/T1.5.md`. A function renamed last month therefore reads as present, which is
   the drift AC1 exists to catch. Adding `-w` and bounding the search with a pathspec
   (`-- src scripts drizzle e2e`) would make the answer a fact about the code.

   the backstop, so this is the order of the run rather than an unmet criterion — naming it so
