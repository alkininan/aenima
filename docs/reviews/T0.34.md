## Findings

**1. Must — `harness.md:16` cites `docs/log/T0.34.md` for a rule the log does not carry.**

`.claude/rules/harness.md:16`:

    - A name out of a document reaches a child process as an argument in an array and never as a shell line. — `docs/log/T0.34.md`

The log entry's account of the script (`docs/log/T0.34.md:11-16`) says where names are looked up
and what is never looked up; it does not say a word about how a name reaches git. The only place
that rule is written is the comment on `gitLook` (`scripts/run/claims.mjs:177-178`). This is pass
4's Must in the same shape: a line whose source exists and does not hold it, which `rules.mjs:181`
cannot see because it checks the path and not the text. `4a1cfed` removed the `isMain` line pass 4
named and left this one standing on the same citation. The skill this diff writes says a source
is what makes a rule line not an invented one (`SKILL.md:463`), and §5 step 8 as this diff writes
it (`docs/guidelines.md:549-553`) files a line "ending in docs/log/<id>.md" because the log is
where the rule was learned.

Smallest correction: one clause in `docs/log/T0.34.md:12`, after "identifiers go through a
word-bounded `git grep`" — e.g. "each name handed to git as one argument in an array and never as
a shell line" — so the citation holds. Or drop line 16.

**2. Must — a root dotfile is never looked up, and the code's own comment says it is.**

`scripts/run/claims.mjs:130`:

    const looksLikeFile = dot > 0 && EXTENSIONS.has(last.slice(dot));

and `:135`:

    if (/^[A-Za-z_$][A-Za-z0-9_$.:-]*$/.test(name) && name.length > 1) {

A single-segment token beginning with `.` fails both: `dot > 0` excludes `.gitignore` and
`.worktreeinclude`; `.env.migrate`'s last segment is `.migrate`, which `EXTENSIONS` does not hold;
and the identifier pattern requires a letter, `_` or `$` first. So every one of them reaches `:139`
and is skipped as "not a path or an identifier" — observed above over a fixture naming two files
main tracks and two it does not. Build 1 says "path-like tokens checked as files" and AC1 says
"every backticked path ... that `origin/main` lacks"; a file name at the root is a path by any
reading, and it is the shape the harness's own tickets name most — this ticket's Cited text names
`.env.migrate`, `.env.local`, `.env.example` and `.worktreeinclude` some twenty times. The comment
on `ownSections` at `claims.mjs:50-51` says checking the Cited section "would report
`.env.migrate` ... as drift on every ticket that cites guidelines §5"; on the code as written it
would not, so the diff believes the token is looked up and it is not.

I am not certain the ticket's author counts a dotfile as path-like, and the miss is in the
conservative direction — a name never reported, never a false one, which is the direction open
question 2 already defends — so this is an uncertain Must rather than a sure one. It is tagged
Must because the ticket's words cover it and the diff's own comment claims the opposite of what
the code does.

Smallest correction: at `:130`, count a single-segment token whose only leading character is a dot
as a file name — `(dot > 0 && EXTENSIONS.has(last.slice(dot))) || (segments.length === 1 && dot === 0 && last.length > 1)`
or the equivalent — with one `classify` case in TC1 (`.gitignore` → path, reddened by removing
the clause). `:50-51` then becomes true as written. `.claude` resolves as a tree and stays
present; `.next` and `.env` read absent, which is true of main.
