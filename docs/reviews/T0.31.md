## Findings

1. **Must — `shellRun` now looks for the cluster in the script's own arguments, and stops reading
   the script when it finds one.** `scripts/hooks/guard.mjs:865` is

   ```js
   if (!SHELLS.has(name) || rest.some(isCommandFlag)) return [];
   ```

   `rest` is everything after the shell's name, the script path and its arguments included. A word
   after the script is the script's argument, not the shell's, so a flag-looking argument now hides
   the file. Measured against `origin/main`'s guard with the same inputs: `bash post.sh -lc` and
   `sh post.sh -vc extra`, where `post.sh` holds
   `curl -X PATCH https://api.notion.com/v1/pages/p -d @s.json`, are **refused on main and allowed
   at this commit** — rule (i) read the script on main, and here `readScript` is never called at
   all. The same transition holds for every shell in `SHELLS` and for a script argument anywhere in
   the tail. No test covers it, and `GUARD_CORPUS`'s entry "run a shell script that writes the
   Notion API" (`scripts/run/loosening.mjs:193-198`) is `bash ready.sh` with no arguments, so step
   9's measurement cannot see the narrowing either: a ticket that tightens the guard would merge
   itself carrying a rule (i) it loosened. *Smallest correction:* read the cluster only among the
   words before the first operand —

   ```js
   const end = rest.findIndex((token) => !token.startsWith("-"));
   const options = end === -1 ? rest : rest.slice(0, end);
   if (!SHELLS.has(name) || options.some(isCommandFlag)) return [];
   const script = rest[end];
   ```

   — with a test that `bash post.sh -lc` still reads `post.sh`. `parse()`
   (`scripts/hooks/guard.mjs:472`) has the mirror of this, `findIndex` over the whole tail, but it
   errs the safe way: it parses a word that is not a command string as one more command line, which
   refuses more, never less. Worth fixing in the same shape.
