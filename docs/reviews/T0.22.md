## Musts

1. **Must (uncertain whether a run would read it this way, not about the consequence).** Nothing
   says what `tried` holds on a second or third pass, or which model that pass starts on.
   `.claude/skills/ticket/SKILL.md:298-299`: "ask the script, with every model the review has been
   called on so far, in order". `scripts/run/review-model.mjs:87` says the same. Here is the usual
   case: Fable is out of credits and pass 1 comes back FINDINGS. Pass 1 was called on `fable`
   (refused), then `opus`. Pass 2 is re-invoked without `model`, so it goes to `fable` again and is
   refused. "Every model the review has been called on so far" is then
   `["fable","opus","fable"]`. `nextReviewer` compares that with `chain[i]` (`review-model.mjs:100`),
   `chain[2]` is undefined, and it answers `stop: true`: "the models tried … are not the start of
   the configured chain". The skill then sends the ticket to Decision. If a run instead starts
   pass 2 on `opus`, the model that worked, any refusal gives `tried: ["opus"]` and the same stop.
   Either way the fallback the Build asks for does not happen on pass 2. Most tickets need a
   second pass, and this ticket exists so a run follows the rule instead of improvising one.
   Smallest fix: in skill step 5 (and the docstring at `review-model.mjs:87`), say that each pass
   starts again at the pinned model and that `tried` is the models called for this pass only, in
   order. Then add that phrase to the TC1 test "is what the skill's step 5 tells a run to do"
   (`scripts/run/review-model.test.mjs`).
