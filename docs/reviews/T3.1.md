## Findings

No Must stands. Five Shoulds, ranked.

1. **Should: `refine-file.ts` creates a new item every run, and the report says it does not.**
   - `scripts/refine-file.ts:345-368`: `const itemId = randomUUID(); const artifactId = randomUUID();`
     then unconditional inserts of `item`, `artifact` and version 1.
   - `docs/reports/T3.1.md:430-431`, open question 8: "The script already reuses one item per file,
     so re-running this document adds versions rather than items." That is `score-file.ts:128-176`,
     which finds an existing item by title before inserting; `refine-file.ts` never looks.
   - Since `refinement_round` and `artifact_version` are append-only and the seed workspace cannot
     be reset (the same open question), every re-run of one document adds a permanent item.
   - Smallest fix: reuse as `score-file.ts` does — select the item by `title` in the seed product,
     insert item and artifact only when none is found — or correct the report's sentence.

2. **Should: once a (artifact, section, check) surfaces, no later version can be argued on it.**
   - `drizzle/0015_refinement_round.sql:67-77`, `refinement_round_shape`: `surfaced` is round 3 and
     nothing is round 4; with `refinement_round_key` on `(artifact_id, section_id, check_id, round_no)`
     the key admits three rows ever, across every future version of the artifact.
   - `src/lib/authoring/rounds.ts:106`: `nextMove` returns `closed` for that key from then on.
   - This is the addendum's key as accepted, and the report records it as default 4 ("The count
     never resets"). What it does not record is who owns the re-open: when the human answers the
     open question and the section changes, the critic can never re-test that check on that section
     through the loop. T3.2 ("the human answers") is the first ticket that will need a path.
   - Smallest fix: add it to the report's open questions with owner T3.2 — no code change here.

3. **Should: binding reads the whole pack while the critic is shown only the checks in play.**
   - `src/lib/authoring/objection.ts:68`: `bindObjections` binds against `allChecks(pack)`.
   - `src/lib/authoring/run.ts:98`: the critic is sent `applicableChecks(pack, conditions)`.
   - An objection naming `prd-15` on a run where its condition did not hold is admitted and can spend
     two revisions and an open question on a check §4 took out of the denominator. The report's open
     question 1 calls it cheap; it is also one line: add `checkIds.includes(objection.checkId)` to the
     door filter at `loop.ts:150-155`, with one test beside the scope-door one. AC1's wording
     ("absent from the loaded pack") is met as written, which is why this is not a Must.

4. **Should: the version's `activity` row names the trigger as the actor, not the author agent.**
   - `src/db/queries/refinement.ts:151-166`: the `artifact_version` row is attributed
     `authored_by_kind = 'agent', authored_by_agent = 'author'`, but the `artifact.version.added`
     activity it writes carries `write.actor` — `refine:file` today, and a human once an item page
     calls `refineArtifactSection` with a human actor. The ledger would then say a human added a
     version that the version row says an agent authored.
   - Smallest fix: the version's activity row uses `actor_kind = 'agent', actor_agent = AUTHOR_AGENT`
     with `trigger_source` derived from the input actor as now; the round's own `refinement.<outcome>`
     row keeps `write.actor`.

5. **Should: `refine-file.ts`'s setup inserts write no `activity` row.**
