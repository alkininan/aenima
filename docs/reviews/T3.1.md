2. **Should: a long heading is not turned away before the paid calls, only at the database.**
   - `drizzle/0015_refinement_round.sql:55` caps the id at 200 characters:
     `CHECK (length(btrim("section_id")) between 1 and 200)`.
   - `slugOf` (`src/lib/authoring/sections.ts:45-52`) sets no length limit, and `refineSection`
     (`src/lib/authoring/loop.ts:105-111`) checks the preamble but not the id's length.
   - A `##` heading whose slug runs past 200 characters therefore goes through a critic call and an
     author call. Then `writeRound` fails, and `refineArtifactSection` reports `write` on every attempt.
   - Pass 1's Should 5 fixed this for reason, evidence and position; the section id was missed.
   - Smallest fix: return `no-section` (or `not-refinable`) when `sectionId.length > 200`, before the
     first call, with a test beside the preamble one.

3. **Should: `route-types.mjs` does not count metadata route files.**
   - `ROUTE_FILE` (`scripts/run/route-types.mjs:43-44`) matches page, layout, route and the special
     files only.
   - Next 16's `discoverRoutes`, which `next typegen` calls, also turns metadata files (`sitemap.ts`,
     `robots.ts`, `icon.tsx`, `opengraph-image.tsx`, `manifest.ts`) into routes
     (`node_modules/next/dist/build/route-discovery.js:195`).
   - A branch that adds one of those would keep a stamp that reads `current` over stale `routes.d.ts`.
     That is the same failure AA4 exists to prevent, on a route kind the app does not use yet.
   - Fix: add the metadata file names to the matcher, or ask Next's own `isMetadataRouteFile`.
