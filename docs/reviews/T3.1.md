## Findings

1. **Must: three schema choices the ticket never defines went out as cheap defaults.**
   `docs/reports/T3.1.md:227-231`: "Said in the claim's one `default` comment on the board row, each
   cheap to change: 1. **A fourth outcome, `held`** … It is in migration 0015, so it is the human's to
   strike before `apply`." `drizzle/0015_refinement_round.sql:28` puts `'held'` into the
   `refinement_outcome` enum and gives it an arm of `refinement_round_shape`. Lines 52–53 add
   `revised_version_id` and `outside_sections`, and neither the ticket's Build nor the addendum names
   those columns (the addendum lists "the version it tested, the section, the check, the round number,
   the objection, the outcome"). The stored `section_id` value `_preamble` (default 2) is the same kind
   of choice.
   - guidelines §4 counts any choice that "touches the database schema or stored data" as expensive,
     and CLAUDE.md says "Never invent endpoints, fields, or columns the ticket does not define."
   - Once applied, an enum value cannot be dropped, so these are not "cheap to change". The run was
     stopping for `apply` anyway, which makes this a mislabel rather than a missing stop.
   - Smallest fix: move `held`, `_preamble`, `revised_version_id` and `outside_sections` out of
     "Defaults taken" and into the ticket file as the questions the `apply` stop puts to the human,
     each with its default. Then `apply` answers them rather than just applying a migration.
   - I am unsure about the two columns. They can be read as part of "their outcomes". `held` is the
     clear case.

2. **Must: the Done line and the red-first record are not met at this commit.**
   - The ticket's Done asks for "one recorded end-to-end run: a section drafted, objected to, revised
     in scope, and a third disagreement surfacing as an open question". The report says
     (`docs/reports/T3.1.md:185`) "the third disagreement surfacing as an open question is not yet on
     record from a live model."
   - The nine `refinement.db.test.ts` rows (`docs/reports/T3.1.md:164-172`) read "not yet observed —
     waits on `apply`". Until they run, nothing has checked `readRounds`/`writeRound`'s SQL, the key,
     the shape constraint, append-only or RLS.
   - No code change settles this now. It is settled by the post-apply steps the report lists
     (`docs/reports/T3.1.md:253-260`): redden each database test and fill its row, record the
     surfacing run, regenerate `database.types.ts`, then review again. The report states all of this
     openly. This finding only records that a PASS at `0c8c5df` would claim more than has been observed.

3. **Should: `scripts/run/route-types.mjs:92` contains a literal NUL byte.** The line
   `].join("\n<NUL>\n")` has a raw 0x00 byte where it should have the escape `"\n\0\n"`, so git treats
   the whole file as binary (`scripts/run/route-types.mjs | Bin 0 -> 5659 bytes`). Its hunks do not show
   in `git diff` or on the pull request. That is a harness script every preflight runs, and whoever
   merges the PR will not see its text. Fix: write the escape `"\0"` instead of the raw byte.

4. **Should: an unchanged section can be recorded as `revised`.** `src/lib/authoring/loop.ts:191`
   (`revisedBody === body ? "held" : "revised"`) compares bytes exactly, and `spliceSection`
   (`sections.ts:170`) only restores a single trailing `\n`. A section stored as `…\n\n`, returned by
   the author unchanged except for the blank line, cuts a new version with a `refinement.revised`
   activity row, even though nothing changed. That new version invalidates §5's cache for no edit.
   Fix: compare with trailing blank lines normalised, or restore the original run of trailing line
   breaks.

5. **Should: the database caps text lengths that nothing upstream caps.** 0015 caps `reason`,
   `evidence` and `author_position` at 2000 characters (lines 57–61). `criticAnswerSchema` and
   `authorAnswerSchema` (`src/lib/authoring/schema.ts:13-30`) set no bound, and the loop does not
   check. An over-long quote or position therefore fails `writeRound` after a paid author call, and
   `refineArtifactSection` reports it as `write`. Related: the pass-limit `throw` at `loop.ts:224` is
   also reported as `write` (`run.ts:130-137`). Fix: discard over-long objections at admission (or
   bound them in the schema) and give the pass limit its own reason.

6. **Should: many tests name no criterion.** `run.test.ts` (7), `loop.test.ts` › "how a round ends"
   (4) and › `draftSection` (2), `prompt.test.ts` › `renderChecks` (2) and › `revisionRequest` (1),
   `objection.test.ts` › `admitObjections` (6) and `scope.test.ts` › `sectionsTouched` (2) appear in
   no Criteria row of the report's AC table. They cover Build items and the report's defaults (the
   checks in play, `critique` metering, draft refusal, `held`), which have no AC. Fix: name the Build
   line or default each one covers, so a later ticket can retire them.

7. **Should: `writeRound` does not check it is revising the newest version.**
   `src/db/queries/refinement.ts:150-161` cuts the next version without checking that
   `round.versionId` is still the artifact's newest. A version added while the loop runs would be
   replaced by a body built on the older one. Nothing writes concurrently today. Worth a guard
   (`where` on the newest version, or a compare in the transaction) before T3.2 adds an editor.

8. **Should: the surfaced question can quote a position for a draft the document never kept.**
   `nextMove` (`src/lib/authoring/rounds.ts:99`) takes the latest round's `authorPosition` whatever
   its outcome. When round 2 was `refused`, the surfaced question carries the position of a revision
   that is not in the document. Consider the latest `revised` or `held` position, or record which
   round the position came from.

9. **Should: a new purpose is missing from an old test's list.** `src/lib/ai/call.test.ts:267-274`
   ("still accepts every purpose that does route on a tier") does not list the new `critique` purpose.

10. **Should: a code comment and the report disagree about the cut-off call.**
    `src/lib/authoring/schema.ts:39-42` says the cut-off draft "spent about 3,400 of a 4,000-token
    ceiling thinking". The report (`docs/reports/T3.1.md:190-192`) says it "spent 4,000 output tokens
    and returned about 2,500 characters of JSON". One of them is out of date.
