## Findings

1. **Must** — `scripts/run/premerge.mjs:66-72`, `confined(ours, theirs)`. It compares the
   branch's build log with main's after blanking the generated sections, and never reads the
   merge base (`git show :1:<file>`). So a branch that added a passage main never touched —
   which git merges cleanly, conflicting only inside the generated sections — is refused at
   `:166-169` with `why` reading "where both sides wrote different words", when one side did.
   AC1 says "a branch whose only conflict with main is in generated files merges"; this one
   does not. It is not hypothetical: `git merge-tree --write-tree HEAD origin/t0-26` puts
   t0-26's only build-log markers at lines 88–95, inside "Tickets done" (`:30`–`:97`), and its
   prose hunks at `:1158` and `:1180` are one-sided — t0-26 is one of the two pull requests
   the Objective names. Reproduced on the test's own fixture plus one line appended to
   "Decisions made during the build" on `t9-2` alone: git's markers land at 8–12 and 25–29
   (Current state, Tickets done) and `premerge` answers
   `ok: false … conflicts outside its generated sections, where both sides wrote different
   words`. The docstring at `:13-16` promises "a hand-written passage … that both sides
   changed" is what gets refused; the code does not check "both". Smallest correction: read
   `:1:` as well; when `withoutGenerated(theirs) === withoutGenerated(base)` take `--ours`
   (the branch's prose) instead of `--theirs` and regenerate as now; refuse only when the
   stripped ours, base and theirs are three different texts — and let `why` say which side
   wrote. Add the one-sided case to `premerge.test.mjs` beside "refuses a build log whose
   conflict is outside the generated sections".

2. **Must** — `.claude/skills/ticket/SKILL.md:450-453`, step 9, the `ok: false` path: "post
   one `refused` comment …, set the task `Review` with the commit it has, release the marker,
   and exit". That exit comes before `git push -u origin <branch>` at `:456` and before
   `gh pr create` at `:457`, so nothing reaches origin and no pull request exists.
   `scripts/run/branch.mjs:53` and `:68` hold the invariant "every exit pushes" and `heldBy`
   removes the worktree on that assumption; this diff's own line in `docs/guidelines.md` step
   9 reads "commit, take main into the branch (premerge.mjs), push branch, open the PR" with
   no exception, and `scripts/run/README.md` step 9 says the same. The consequences: the
   board's Commit names a commit nobody can fetch; the human's `merge` at step 0 has no pull
   request for `gh pr merge t<id>` to act on; and `branch.mjs` at that step 0, finding no
   `origin/t<id>`, runs `checkout -b t<id> origin/main`. The ticket says a non-generated
   conflict is "refused as now … and the task stays at Review" — as now, the branch is on
   origin under a pull request. Smallest correction: in that path, push and open the pull
   request first, then post the refusal and set Review — or move the `premerge.mjs` call after
   the push/PR lines and push again on `merged: true`.
