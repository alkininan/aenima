## Findings

1. **Must — the red-first row for "reads a two-digit number as one number" records a mutation
   that leaves the test green.** `docs/reports/T0.28.md:37` reads:

       | `nextId` "reads a two-digit number as one number, not as its first digit" |
       `idOf`'s `\b` removed, so `T0.98` reads as 9 and the answer moves from T0.9 to T0.10 |
       1 failed / 23 passed → 24 passed |

   `idOf` is `/^T(\d+)\.(\d+)\b/` (`scripts/run/next-id.mjs:41`). Removing the `\b` leaves
   `(\d+)` greedy, so `T0.98 Smoke A` still reads as 98 — checked both regexes against that
   string: `["0","98"]` either way. Under the recorded mutation the test passes and the count
   would be 24 passed, not 1 failed. So the row is not a record of an observation, and §5 step 8
   refuses a report without one. This is the row pass 1's Should 1 created, which is the one
   place a false mutation matters most: the reason the test was strengthened is the reason its
   mutation has to be the real one. *Smallest correction:* record the mutation that does redden
   it — narrowing `idOf`'s second group from `(\d+)` to `(\d)`, which reads `T0.98` as 9 and moves
   the answer from `T0.9` to `T0.10` — run it, and record the count it actually gives. Note that
   `docsIds`' "reads a two-digit number as one number" reddens under that same mutation, so the
   count is at least 2 failed and that row's mutation cell wants the same treatment.

2. **Must — `repoTaken` reads `docs/` under `process.cwd()`, and a missing `docs/` is exempted
   from `unread`, so the script can answer a number `docs/` holds and call the read complete.**
   `scripts/run/next-id.mjs:100-105`:

       try {
         entries = readdirSync(join(cwd, DOCS_DIR), { recursive: true });

         if (error?.code !== "ENOENT") unread.push("docs");

   T0.1 is the scaffold ticket's, `docs/tickets/T0.1.md` carries it, and `unread` is empty — the
   repeat this ticket exists to stop, answered as a full read. It is the same hole pass 1's
   Should 4 named, left open by the carve-out the fix added: "a checkout that has no `docs/` tree

   `docs/` is tracked on main. The AC3 tests do not reach it — `repoTaken`'s "no docs tree" test
