   nothing put in its place.** Build item 2 gates "the gate's commands reduced", and
   `scripts/run/loosening.mjs:281` `gateLoosened` compares only `before.steps` against
   `after.steps` and `maxRed`. But `STEPS` is `["lint", "typecheck", "test"]`
   (`scripts/hooks/gate.mjs:58`) and the gate runs them as `spawnSync("pnpm", [step])`
   (`scripts/hooks/gate.mjs:253`) — the commands live in `package.json`, and this diff deletes the
   `scriptsChanged` comparison that watched them (`scripts/run/gated.mjs`, the removed
   `GATED_FILES`/`scriptsChanged` block, and with it `gated.test.mjs`'s "is not ok when the scripts
   of package.json changed, and names the file"). Measured here over a temporary repo whose one
   commit sets `"lint"`, `"typecheck"` and `"test"` to `"true"`: `loosenedBy` answers
   `{ ok: true, reasons: [] }` and `gatedDiffOf(...).ok` is `true`. A diff that empties the Stop
   gate merges itself unattended, which is the one thing the ticket keeps for the human.
   Smallest correction: a rule in `loosening.mjs` that reads `package.json` on both sides — `git
   show <base>:package.json` against the checkout's — and emits a reason when a `scripts` entry
   named in `STEPS` differs, with a test and a row in the red-first record.

2. **Must — a hook deleted from a group that holds two is not seen.** Build item 2 gates "a hook
   removed from `.claude/settings.json`". `scripts/run/loosening.mjs:233` writes
   `found.set(`${event} ${matcher}`, String(hook?.command ?? ""))` inside the loop over
   `group.hooks`, so a group with more than one hook keeps only the last command. The repo's own
   `.claude/settings.json` has exactly such a group: `SessionEnd` `*` holds `release.mjs` and
   `runs.mjs`, and `hooksOf` records only `runs.mjs`. Deleting the `release.mjs` hook from that
   group and asking `hooksLoosened(before, after)` answers `[]`. Smallest correction: key each
   hook separately — `${event} ${matcher} #${index}`, or keep a list of commands per key and
   compare the two lists — and a test with a two-hook group, one removed.

## Shoulds

1. `docs/build-guide.md` still states the rule this ticket replaced: line 2 ("your word stays for
   the gated paths") and line 109 ("a pull request on a gated path — a migration, the product
   spec, the pipeline's own guard, gate, skill or run scripts — merges on the word `merge` at
   Review"). Both are now false. T0.16 bumped the build-guide to v2.6 for exactly this reason;
   v2.7 with the one sentence would settle it.
2. The v1.12 header says "§1 and §3 say it that way". §1 is Structure and carries no sentence
   about merging; the cell that changed is in §2 Databases, under Releases
   (`docs/guidelines.md:143`). Say §2 and §3.
3. `.worktreeinclude` is ungated now and nothing measures it, while guidelines §5's capability
   boundary rests on it: "`.env.migrate` … is gitignored, and `.worktreeinclude` does not carry
   it". A diff adding `.env.migrate` to that file hands every worktree the admin credential and
   self-merges. Guard rule (b) still stands as the second layer, so this does not block; a
   one-line rule — the after side must name no `.env` file the before side did not — would make
   it a measurement rather than a hope.
4. Every head-side reading is the working tree, not `HEAD`: `loosening.mjs:476`
   `probe(join(cwd, "scripts"))`, `:510` `readHead(cwd, ".claude/settings.json")`, `:513`
   `filesOf(cwd, range, "A", null)`. The guard's door binds the pull request's head to the
   checkout's HEAD so that "the diff the guard read is the diff that merges", and an uncommitted
   tightening in the tree would mask a committed weakening in the commit that merges. Reading the
   head side with `git archive HEAD scripts` the way the base side is read would close it. (The
   same shape was in T0.16's `headPackage`, so this is inherited, not introduced.)
5. Thirteen tests in `loosening.test.mjs` name no criterion — the three after the first in
   `describe("the corpus")`, `ruleLetters`, `pathsLoosened`, the four `hooksOf and hooksLoosened`
   cases, the two `gateLoosened` cases, the four `testsLoosened` cases and "gates a diff whose
   before side cannot be read". They cover Build item 2's hook, gate and deleted-test bullets,
   which no AC names, so nobody can retire them against a criterion. Worth an AC7 in the ticket or
   a tag on each. The convention is load-bearing here: `testsLoosened` reads an untagged test file
   as one nothing can replace. `gatedDiffOf` — the function the skill and the guard actually call,
   and the one this diff rewired — still has no test of its own; the repo-level cases stop at
   `loosenedBy`.
6. `probe` (`loosening.mjs:409`) spawns with no timeout, and `loosenedBy` runs on the guard's path
   to `gh pr merge`. A probe that hangs hangs the guard rather than refusing. A timeout, read as a
   side that could not be measured, keeps the conservative answer.
