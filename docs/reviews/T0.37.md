## Findings

1. **Should** (carried from pass 2's 2) — §8.18's typed-letter jump is not built for the menu.
   `src/components/ui/Menu.tsx:141` `onKeyDown` handles Tab and what `nextRovingIndex` walks;
   `matchTypeahead` is not imported. §8.18: "a typed letter jumps to the next row starting with
   it." C-46 owns the check and this ticket does not cite it, so no AC claims it. Either add the
   clause (as `Select.tsx`'s `jump`) or carry it in the report's open questions with C-46's
   owner.

2. **Should** (carried from pass 2's 3) — The two placement paths can still diverge at the
   viewport's edge. `src/lib/panel-placement.ts:89` clamps `left` to the viewport;
   `src/components/ui/Panel.tsx:124` derives `data-align` from `placement.left === rect.left`,
   so a clamped panel reads as `end` and the anchored path writes `right: anchor(right)` with no
   clamp. §6: "the two must be pixel-identical." Unreachable at the kitchen-sink's widths, which
   is why the rect comparison passes. Drop the clamp, or carry it into the anchored path.

3. **Should** (carried from pass 2's 4) — AC2 claims C-10 and C-11 whole; only their row clauses
   are built and tested. `e2e/panel-geometry.spec.ts:71-77` defers C-10's `::before` floor
   extension to the report; nothing samples C-11's "pipeline strip's segments"
   (`src/app/app/PipelineStrip.tsx` exists). Record both in the report as open questions with an
   owner, or restate AC2 as the row clauses.

4. **Should** (carried from pass 2's 5) — `Panel` reads a ref in a layout effect that a passive
   effect refreshes. `src/components/ui/Panel.tsx:99` `focusRef.current = focusOnOpen` sits in a
   bare `useEffect`, and the open layout effect calls `focusRef.current?.()` on the render where
   `open` turns true — so on the bare path the callback is the closed render's closure. The
   select's cursor effect refocuses the intended row before paint, so no outcome changes today.
   Make that ref-sync a `useLayoutEffect`.

5. **Should** (carried from pass 2's 6) — A showing toast replays its entrance and restarts its
   clock whenever a modal opens or closes beneath it. `src/components/ui/Toast.tsx:161` switches
   between `createPortal(viewport, host)` and `viewport`, which remounts the region, the slot
   (`:184` reseeds `shown`) and the item — a fresh `@starting-style` rise and a fresh
   `remaining`. §8.20 says the host is "moved" into the modal; a move keeps its clock. Reasoned
   from React's tree identity, not measured. Move the one node imperatively, or key the timer on
   the toast's id in a ref that survives the remount.

6. **Should** (carried from pass 2's 7) — The mid-morph sample can skip itself and is not strict.
   `e2e/morph.spec.ts:129` `test.skip(Number.isNaN(sampled), …)` turns a missed sample into a
   skip, and `:130-131` allow equality within 1; C-14 says the width "lies strictly between".
   Sample every frame as the `morph-content` test does and assert strictly.

7. **Should** (carried from pass 2's 8) — Two cited clauses are exercised only where they cannot
   fail. `e2e/morph.spec.ts:250` crosses the 8 onto a tooltip on the page; C-16 says "a tooltip

   `src/components/ui/Tooltip.dom.test.tsx:96` pins the non-flipping branch only; nothing shows
   the flip to `top` when the room is short. Add both.
