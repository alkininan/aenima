## Findings

1. **Should** — An undo can fire twice inside its own exit. `src/components/ui/Toast.tsx:243`
   `fire` runs `action.onAction()` then `close()`; closing makes the slot render the same
   `ToastItem` with `leaving` (`Toast.tsx:195`), and for the `--t-fast` exit the Undo button stays
   pressable and the `Cmd/Ctrl+Z` listener at `Toast.tsx:264` stays installed, so a second press or
   a double-click in that window calls `onAction` again. Before this diff the toast unmounted on the
   frame it closed, so the window is new. Tagged Should for its width — one `--t-fast` — not for its
   shape. Smallest correction: guard `fire` on `!leaving` and make the keydown effect return early
   when `leaving`.

2. **Should** — §8.18's typed-letter jump is not built for the menu. `src/components/ui/Menu.tsx:141`
   `onKeyDown` handles Tab and whatever `nextRovingIndex` walks (arrows, Home, End); nothing matches
   a printable key, and `src/lib/typeahead.ts` — which the select already uses — is not imported.
   The Build line says "their keyboard contracts"; §8.18: "a typed letter jumps to the next row
   starting with it". C-46 owns the check and this ticket does not cite it, so AC1–AC6 do not claim
   it. Either add the clause (`matchTypeahead` over the rows' labels, as `Select.tsx`'s `jump`) or
   say so in the report's open questions with C-46's owner.

3. **Should** (carried from pass 1's 9) — The two placement paths can still diverge at the
   viewport's edge. `src/lib/panel-placement.ts:89` clamps `left` to the viewport;
   `src/components/ui/Panel.tsx:124` derives `data-align` from `placement.left === rect.left`, so a
   clamped panel reads as `end` and the anchored path writes `right: anchor(right)` with no clamp.
   §6: "the two must be pixel-identical." Unreachable at the kitchen-sink's widths, which is why
   the rect comparison passes. Drop the clamp, or carry it into the anchored path.

4. **Should** (carried from pass 1's 11, extended) — AC2 claims C-10 and C-11 whole; only their row

5. **Should** — `Panel` reads a ref in a layout effect that a passive effect refreshes.
   `src/components/ui/Panel.tsx:99` `focusRef.current = focusOnOpen` sits in a bare `useEffect`, and

   the bare path (no `startViewTransition`, reduced motion, `data-force-fallback`) the callback is
   the closed render's closure, whose `activeIndex` is −1. The select's cursor effect refocuses the
   intended row before paint, so no outcome changes today; the shape is one render from being
   wrong. Make that ref-sync a `useLayoutEffect`.

6. **Should** — A showing toast replays its entrance and restarts its clock whenever a modal opens
   or closes beneath it. `src/components/ui/Toast.tsx:161` switches between `createPortal(viewport,

   the item — a fresh `@starting-style` rise and a fresh `remaining`. §8.20 says the host is "moved"
   into the modal; a move keeps its clock. Not measured; I am reasoning from React's tree identity
   rather than from a rect. If it shows, move the one node imperatively (`host.append(node)`) or key
   the timer on the toast's id in a ref that survives the remount.
