1. **Must — `consumedApplies` is the run's half of AC1 and nothing tests it.**
   `scripts/run/gated.mjs:133`, `export async function consumedApplies(...)`. Five distinct
   returns — no marker, no token, the board file unreadable, the thread unreadable, and the
   tags — and not one of them is exercised anywhere on the branch; `grep` over `scripts`, `src`
   and `.claude` finds the name only in `gated.mjs`, `scripts/run/README.md:225` and
   `docs/log/T0.26.md:41`, where it carries a claim: *"`consumedApplies`, which fails closed on
   every path: no marker, no token, no board file, a thread that would not load — each one
   answers with no tags."* That claim is untested, and it is not a side path: AC1 says the diff
   **self-merges**, and the self-merge is the run reading `ok: true` from `node
   scripts/run/gated.mjs` at step 9 (SKILL.md §9), which is this function. The guard's half of
   the same question is tested twice over (`permission.test.mjs:379`, `guard.test.mjs:1333`);
   the command-line half is tested nowhere. CLAUDE.md, *Done means*: "New logic has tests";
   guidelines §5 step 4: "new logic has tests observed failing first, the mutation and the count
   recorded per test."
   *Smallest correction:* a describe in `scripts/run/gated.test.mjs` over
   `consumedApplies({ dir, deps })` — the deps are already injectable (`marker`, `token`,
   `board`, `comments`) — one case per return, the happy path asserting the tags come back from
   a thread carrying `migration` → `apply` → `applied`, named TC1 → AC1 and TC2 → AC2, each
   observed red first with its mutation and count recorded.

2. **Should — a migration written the way CLAUDE.md prescribes carries a third file `coveredBy`
   can never cover.** `scripts/run/gated.mjs:66-75`. `isGatedPath` gates everything under
   `drizzle/`, and `coveredBy` can lift only a `*.sql` whose tag is spent and
   `drizzle/meta/_journal.json`. `pnpm db:generate` — CLAUDE.md's `db gen` line, and the only
   sanctioned way to write a migration here — also writes `drizzle/meta/<nnnn>_snapshot.json`,
   which `migrationTag` answers `null` for and which therefore stays on the gated list with the
   apply fully spent. AC1 would not fire on that diff. Nothing is broken today: the repo's last
   fifteen migrations are hand-written SQL plus a journal line (`drizzle/meta/` holds only
   `0000_snapshot.json` and `0001_snapshot.json`), and the failure is closed rather than open.
   *Smallest correction:* give the snapshot the journal's treatment — covered when the migration
   whose number it carries is — or say in the report that the rule is for the hand-written shape
   and a generated migration still waits for `merge`.
