### Must

**1. A lookup that fails buys a skip, and four places say it cannot — `src/test/migration-gate.ts:45`.**
`return blob.status === 0;` reads every non-zero `git cat-file -e` status as "not on main", and
`cat-file -e` answers **128** for an absent path and 128 for any fatal alike — observed on this
checkout: `fatal: path 'drizzle/0099_missing.sql' does not exist in 'origin/main'`, status 128. So
once `origin/main` resolves, a lookup that fails for any other reason answers `landed: false`, and
`gateOf` skips. The ticket's Rule is "the helper must make that impossible, not unlikely", and the
diff claims it has: the helper's contract (`src/test/migration-gate.ts:36-38`, "True whenever that
cannot be established — the ref missing, git absent, the lookup itself failing"), open question
40's ruling (`docs/build-log.md:1167-1169`, "a lookup that fails — … none of them buys a skip"),
the log entry (`docs/log/T0.26.md:53`) and the report's open question 4
(`docs/reports/T0.26.md:292-297`), which records pass 5's Should inverted — "reads every non-zero
`git` status as 'landed'", "*both* buy no skip", "the mechanism is right" — when the code reads
every non-zero status as *not* landed and both buy a skip. The fixture at
`src/test/migration-gate.test.ts:54` pins `status: 1`, a value git does not produce; the branch it
exercises is the one every fatal takes, and "is true when git could not be run for the file
itself" (`:63-72`) covers only a spawn error, which cannot happen once `rev-parse` has just run.

Smallest correction: make absence its own answer. `git ls-tree --name-only origin/main -- <file>`
exits 0 for a resolved ref whatever the path — observed: empty stdout for an absent path, the name
for a present one, 128 for a bad ref. Then `error` or a non-zero status → `true` (cannot be
established), status 0 with empty stdout → `false` (the one case that may skip), status 0 with
stdout → `true`; `GitRun` carries `stdout`, the four fixtures follow, and open question 4 in the
report is closed or says what the code then does. Correcting only the four descriptions to say a
failed lookup skips would make the account true but leave the Rule unmet, so the code half is the
one that settles it. I am uncertain of the tag: the window is a git fatal on a ref that resolved
a moment earlier. I tag it Must because the ruling, the contract and the report all claim the
case is closed and it is not, and a false account of the mechanism was pass 4's Must.
