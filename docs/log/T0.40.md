# T0.40 — Tokens and fonts to v2.21
_2026-09-22T17:47:52Z_

The token layer is design-spec v2.21's, verbatim and in both directions. `globals.css` carries §2,
§5 and §6's CSS blocks as the document writes them — the glass fill at .85, `--r-panel`, the glass
fallback, the float and modal shadows, the four named long durations and the three delays — and
beyond them only §4's z-ladder, which is prose in the document and neither a colour, a radius, a
duration nor an easing. The components that read a renamed token followed it and nothing more: the
panel's radius, the toast's radius and shadow, the card's quieter specular line, and the sweep,
spinner and skeleton, which had their durations written into them as numbers and now read the
tokens. `motion.ts` holds §6's six script figures and no other, and the three modules that carried
one as a literal import it.

Two faces are vendored. §3 says why — Google's DM Sans carries no `tnum`, so law 6's typed-digits
exception cannot render, and its JetBrains Mono lacks Ĳ ĳ and the ⌘ ⇧ the kbd hint draws — and the
upstream builds were checked before they were cut: DM Sans 4.004 from `googlefonts/dm-fonts` does
carry `tnum` (the same version number as Google's, rebuilt in 2024), and JetBrains Mono 2.305 does
carry ⌘ and ⇧. `scripts/fonts/vendor.py` cuts each into Latin and Latin Extended woff2 files, and
reads the ranges out of the `@font-face` declarations in `fonts.ts` rather than holding a second
copy of them, so the file a browser is told to fetch for a letter is the file that was cut to hold
it. The mono's Latin subset carries ⌘ and ⇧ as well, because neither is in Google's Latin range and
the kbd hint draws them whatever the locale.

Two things the font compiler decides rather than the author, both found by building: every option
in a font call is read out of the source, so a `unicode-range` held in a constant arrives as a
missing value and the ranges are written out four times; and a face loaded in two calls gets two
generated families, whose metric fallbacks would sit between the two subsets and render every
Turkish letter in Arial — so each vendored face declares its family outright and its two calls
share it. Space Grotesk stays the one face from Google Fonts, Latin preloaded, Latin Extended
declared and fetched on demand, which is exactly §3's rule for a page rendering EN.

Which leaves §3's one clause this ticket could not build: Latin Extended is preloaded *when the
locale is TR or NL*, and no locale is resolved per request — `src/i18n` holds `en.ts` alone. The
deferral is recorded as open question 1 in the report, owned by the phase that resolves a locale;
it is not a flag that was forgotten.

The checks read the document. `src/app/tokens.test.ts` compares every custom property, every §3
type token and every script timer against `docs/design-spec.md` in both directions, so a token
added to the stylesheet and not to the document fails as surely as the reverse.
`e2e/fonts.production.spec.ts` asks a real build what it loaded, fetches every face the page
declares and hands the files to fontTools — which is the only way to check the third face, since
Space Grotesk exists only once something has built it.

The review ran on Opus after the pinned model answered out of credits, stopped once at its turn
limit and was resumed, and raised two Musts: no report yet, so no red-first record, and an
unrecorded stopgap. Both are settled by the report. Of its five Shoulds, two were fixed in code —
the token test read only the first CSS block of a section, and two comments claimed a Google face's
family name is generated when the loader keeps it — one became a Backlog Fix (`.glass` still lacks
the `-webkit-backdrop-filter` twin §5 states first), and two are open questions: the tooltip's
delay now exists as both a CSS token and a script constant, and C-39's no-literal clause waits on
the floating label, whose two type sizes are animated and cannot be a class.
