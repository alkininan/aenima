# T0.12 — Telemetry and mirror: every run leaves a row, the mirrors keep up
_2026-09-14T10:44:34Z_

Every `/ticket` session now leaves a Runs row without a model in the loop: the SessionEnd hook runs
`scripts/run/runs.mjs` over the transcript Claude Code wrote and posts task, started, duration,
model, tokens, outcome and findings with the integration token. Tokens are counted once per API
message — a transcript writes one message as one line per content block, each repeating the usage,
and T0.10's table counted the lines, so its numbers were high by that ratio. The Documents and
Guidelines mirrors are refreshed in preflight from `origin/main`: `mirror.mjs` reads each page's
first block over the API and plans the pages behind main, and the skill rewrites each through the
connector — a stopgap until an API writer, owner E0.2, recorded in the report — header-last — a *refresh in progress* callout, the document in chunks, the heading last —
so a page is whole and headed with its commit or visibly in progress, never in between; a sentinel
left standing is refreshed first. CLAUDE, AGENTS and Guidelines were refreshed this run. The debts
of T0.9 and T0.10 are closed with tests (the SessionEnd release observed live, `recover`'s remote
path and `wip` flag, prune's three-hour floor and git-native self-identification, the gate's
`statePath`, nine tests re-reddened by logic mutations) or re-owned to the Runs data (the
fingerprint over untracked files). Guidelines v1.7 at the first round, v1.10 after the addendum.

Two things the board taught: the token in `.env.local` is not a token (17 characters, `401`), so
this run read no comments and the three T0.10 rows went in through the connector rather than the
script; and Notion rewrites a header on the way in — bold split around inline code, bare `x.md`
auto-linked — so the swap of sentinel for heading only matches when the path sits in inline code
outside the bold, the shape probed on a scratch page and shipped.

The addendum round, 2026-09-15, came from a `merge` that could no longer land: T0.16 and then T0.17
merged first over the same passages, and the human's `default` took the fallback — main merged into
the branch, the mirror refresh placed as step 0f after T0.16's deploy check so a revert is what gets
mirrored, and the Runs row placed beside T0.16's self-merge. Main's protocol also changed what a
transcript says: step 0 claims tasks to merge before step 1 claims the run's own, and a stop
releases the marker before it sets Decision. So `runs.mjs` now reads a claim's Status writes up to
the next claim, leaves out a claim that merged before writing a Status of its own, reads Done as
Done, and reads claims and merges with the guard's own shell parser, so a heredoc or a quoted
prompt is not a command. Pass 1 of the round caught the merge dropping §5 step 1 and the first
version of the claim rule losing a Decision; pass 2, a heredoc read as a merge.
