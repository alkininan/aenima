# T0.25 — Review scope against origin/main
_2026-09-21T14:05:32Z_

T0.25 — review scope against origin/main. **A worktree's `main` is whatever the primary checkout
last left it at.** The two scripts that decide what a review covers, `review-scope.mjs` and
`report-check.mjs`, took their diff against the literal `main` when no base was given, and a
scheduled run's worktree never moves that ref. On T1.4's addendum round it sat a merge behind
`origin/main`, so ten test files from T0.24 and T3.1 read as T1.4's. The check refused a correct
report over them, and the reviewer had to set its own scope by hand. Four Backlog filings since
2026-09-15 named the same two scripts. This ticket folded them into one, and every run since then
had worked around the first by passing `origin/main` itself. Both scripts now default to
`origin/main`, from one exported constant. So does the reviewer's own `git diff`, which had the
same defect in `.claude/agents/reviewer.md`.

The other three fixes were in how `review-scope.mjs` reads a ticket. A test path is now read
segment by segment, so `src/app/o/[key]/ItemLine.dom.test.tsx` survives whole rather than coming
back as `/ItemLine.dom.test.tsx`. A test named by its bare file name is read as a precedent in
prose rather than a citation. That is a convention rather than a parse, so a corpus count chose
it: across all 26 ticket files, T1.4's two precedents are the only bare names any Tests section
holds. The comment says what the rule cannot see. And the test files an `## Addendum…` section
names are in scope too, which T2.9's addendum round had needed. Both CLI tests run over a real
temporary repository whose local `main` is one commit behind `origin/main`, because the defect was
which ref git gets asked about, and a stubbed runner would only prove the stub agrees with
itself. Reviewed cold in one pass: PASS, with three Shoulds. One of them is recorded rather than
fixed: a guard comment still says `main...HEAD`, and one word is not worth an unreviewed guard
diff.
