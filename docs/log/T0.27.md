_2026-09-22T12:01:12Z_

T0.27 — extra-high effort for runs. **The scheduled task's form picks a model and has no effort
control.** So every run went at the session default, which is high. Claude Code reads an `effort`
from a skill's frontmatter and from a subagent's, and either one overrides the session's effort
for as long as it is active. So `effort: xhigh` now sits in `.claude/skills/ticket/SKILL.md` for
the whole run and in `.claude/agents/reviewer.md` for every review pass. The model-config table
lists `xhigh` for Fable 5.1 and for Opus 5, so it holds along the whole review chain. The effort
is deliberately not in the repository's settings, because an `effortLevel` there would reach every
session opened in the repository, not only runs. Guidelines §5 names both files at v1.19.

The test reads both frontmatters and asserts the field, and it also checks that the reviewer's
model, turn cap and fallback are what they were. Review pass 1 asked for the Build's "nothing in
settings" to be tested too, so it is. Pass 2 passed. This run cannot see the effort it set: the
session had loaded the skill from before the field existed. The first run after the merge is the
first at `xhigh`, and its own status line is where that shows.
