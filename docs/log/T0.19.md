# T0.19 — Spec: the comment path
_2026-09-15T23:34:33Z_


Product-spec §11 has said since v1.6 that Backlog → Ready is the one transition aenima never makes
for itself. That was written when the confirm was a click. On aenima's own board it stopped being
one at guidelines v1.9: a human's reply beginning with `ready` moves the ticket, and the guard
reads that word from the board over the API before the connector's write goes through. The rule
did not change — the human still makes the move — only the surface it is made on. This ticket
carries that into the product, the way v1.6 carried six rulings before it, so a customer's
developer can unblock a ticket from the thread they are already in rather than leaving it to find
the board.

The paragraph now names the three words a reply can carry and says what makes them safe: each is
verified against the backlog itself, the reply read from the database before the move is made and
never from the model's account of the thread. That last clause is the whole point of the carry. A
model that reports what a thread said is a model that can be wrong about a permission, and the
difference between reading the word and being told about it is the difference between a check and
a claim. *ready* is the one v1 acts on; *apply* and *merge* are bounded to §17's "once aenima
itself drives a coding agent from the backlog", which the spec already puts at v2 — the default
this run took rather than inventing a v1 meaning for two words or leaving them hanging.

The review earned its keep twice. Pass 1 found the v1.7 header line sitting *outside* the HTML
comment: the close still sat on the v1.6 line, so the new one would have rendered as visible prose
between the title and §0, in the file and in the Notion mirror — a correction history in the body,
which the ticket forbids in the same breath as it asks for the line. The grep written for that
criterion had passed it, because it asked whether the line existed and not whether it was header;
it was strengthened to demand the comment's close, and its red is recorded at the commit that had
the defect. Pass 2 then found that the added sentences had stranded "The rest are made by whoever
does the work" two sentences from the status set it referred to, so it read first as the rest of
the words. Both are the same kind of error — prose that is true read slowly and wrong read at
speed — and neither would have been found by anyone who knew what the paragraph was supposed to
say.

The diff touches `docs/product-spec.md`, so it is gated: the run does not merge its own spec
change. It waits at Review for the word.
