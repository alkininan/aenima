# T0.28 — Number task IDs across the phase
_2026-09-22T22:05:00Z_

An ID is supposed to name one task. `next-id.mjs` numbered within the epic — the highest already
used there, plus one — and two epics in one phase counted straight past each other. E0.4 Design
conformance was answered T0.1, which is the scaffold ticket's, and was given T0.40 by hand to get
out of it; E0.1 Foundation is answered T0.7, which is E0.2's Setup. The collision does not show
up anywhere a person would notice, because an ID is not a row in a table: it is a branch name and
a set of file names under `docs/`. The second task simply writes over the first task's record.
R-0062 stopped at claim on the first of these rather than take the number.

The epic now gives the phase and nothing else. The number is the lowest in that phase nobody
holds, and the set of holders is wider than the board: a task, whatever its epic and whatever its
status, or a branch, or a file under `docs/`. That last part is the half that keeps the rule
true over time — `docs/log/T0.97.md` is on main and no task anywhere is called T0.97, so 97 is
spoken for and stays spoken for. An epic owns no block of numbers either, so T0.40 and T0.96 are
stepped over like any other.

Two things were decided about where the rule lives rather than what it says. The script reads the
branches and the `docs/` tree itself, rather than being handed them: a rule a script applies
cannot be the one a run forgets, and this is a rule whose whole job is to be remembered. And
`pick-next.mjs` now prints `names`, every task's Name, because it already reads every row over
the token — the skill was asking the run for "every task name on the board" and no script printed
one, which is how the protocol quietly becomes a thing the model improvises.

The review took all three passes and each one was worth it. Pass 1's Must was the absence of the
red-first record itself, and six Shoulds with it, of which two mattered: a two-digit test that
could not fail for the reason its name gave, and an untested composition — dropping `repoTaken()`
from the CLI left every test green. Writing that composition test found a bug in its own fixture:
`git init` with no commit leaves the branch unborn, so `git branch -a` lists nothing. Pass 2
found `repoTaken` reading `docs/` under `process.cwd()`, which from `scripts/` answered T0.1 with
`unread` empty — the duplicate handed out in silence, in the field added to stop exactly that.
It also caught the two-digit test's red-first row naming a mutation that leaves the test green,
and its own suggested replacement turned out not to redden it either: `\b` alone leaves `(\d+)`
greedy, and `(\d)` alone makes the boundary fail so `idOf` returns null and the answer lands on
T0.9 by another route. Both together are what reddens it. A recorded mutation is a claim like any
other, and this one had to be run twice before it was true.
