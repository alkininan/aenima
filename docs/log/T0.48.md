# T0.48 — Layout modes and chrome
_2026-09-28T16:24:37Z_

The frame is one thing on every route now. `Frame` renders the sidebar or, below 1024, the hand top
bar, then the content column, from the `/app`, `/i` and `/o` segment layouts and from the `/dev` sink
with fixture products, and it says its mode in `--layout-mode` on its own element and never on `:root`,
so a test and later the dock read one signal from the element that carries it. The read-only line is
a gate rather than a branch: `WriteGate` renders every write on the server with `data-writes`, hides
it by CSS under the pointer-600 and touch-768 queries before hydration and empties it from the DOM
after, so the gap move still posts without React having arrived. Below 768 a modal and a side sheet
are one bottom sheet — top corners `--r-lg`, flush with the bottom edge, 90dvh at most, a grabber on
touch that is decoration — and its geometry is unlayered CSS, because a `@layer components` rule
cannot outrank the utilities the surfaces carry at every width. Chrome paints before data: the
layouts await only the session, `readProducts` reaches the switcher as a promise filled by effect
rather than through a Suspense slot — React leaves a pending boundary's fallback un-hydrated, and a
switcher rendered as one was inert exactly while C-40 measures it — and each route's `loading.tsx`
renders the page topbar over the content's skeleton. The budget is its own Playwright project with
the server to itself: under four workers the same route change painted in 468–991 ms that paints in
35–60 ms alone, and C-45 says unthrottled.

Two things the build met on the way. A redirect thrown after the shell has streamed is a meta
refresh in the body and not a 307: a first cut passed the session as a promise too, the production
build answered `/app` with 200, and the session await went back into the layout before the shell.
And the disclosure's glow test, which the first report called a load flake, was a computed read
landing inside `.control`'s 120 ms `box-shadow` transition — early and failing alone, late and passing
under four workers — which the review found and a wait on `getAnimations()` settled. The proxy turned
out not to be running at all, `proxy.ts` standing at the root where Next reads beside `src/app`; that
is a Fix task and not this ticket's, and so is the sheet's drag dismiss, C-23's check the ticket did
not cite. The review's six Shoulds stand as *Shoulds from T0.48*.
