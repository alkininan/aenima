# T3.2 — Chat panel: the ledger first, the dock next
_2026-09-22T23:10:00Z_

The ticket is the item page's chat dock, and what this round built is none of it. It built the
three corrections T3.1 left behind — the ticket's own addendum — because two of them are a
migration, and everything the dock writes lands in the table that migration changes: an open
question is a `refinement_round` row, and a confirmed echo is the human-authored version that
decides whether a surfaced check reopens. Building the surface against a shape nobody had applied
would have been building against a shape that could still move.

**AA1 was a ruling that does not terminate if you read it literally**, and finding that out was
most of the work. "A surfaced check closes for the artifact version, not forever — a new version
of that section reopens it at round zero." The author's own revisions are new versions of that
section: round 1 revises, cutting a version, so round 2 would find no rounds on the new version
and start again at one, for ever. §6's two-round cap is a product-spec law and the literal reading
repeals it. The ruling's own next sentence says what it means — *if the human later rewrites the
section* — so the cycle is keyed to the section's text in the newest **human-authored** version,
hashed. The loop's versions are agent-authored and never move it. That is the whole of why the
column is `base_section_hash` and not `base_version_id`: hashing the section rather than naming
the version is what lets a human rewrite of one section leave every other section's closure
standing, which is what "that section" asks for.

The hash needed one thing the tests found rather than the design: the section parse is lossless,
so a section carries the blank lines that separate it from the next one, and a section moved to
the end of a document loses one without a word of it changing. A baseline that moved on that
would reopen every check on a section somebody reordered. `spliceSection` already treats the
trailing break run as formatting at the seam; `sectionHash` now does too.

**AA3 is §1 law 7 meeting a column width.** T3.1 dropped an objection whose reason or evidence ran
past 2000 characters — a gap nobody hears about, decided by `varchar`. The reason is now cut and
the cut recorded; the quote is cut and recorded too, and because a cut quote is not the verbatim
evidence law 3 asks for, such an objection never reaches the author at all. It surfaces to the
human, at whatever round its cycle is on and with no author position, because the author was
never asked. That last part is why `author_position` stopped being NOT NULL: a position written
in for a question nobody was asked is the ledger saying something that did not happen, and the
shape constraint now requires one of the three outcomes the author actually answered instead.

**AA2 was the small one** and reads as the correction it is: §5 caches results per artifact
version, so applicability belongs to the version, and `readLatestConditions` — the artifact's
newest run — became `readVersionConditions`. A section refined before its first re-score was being
judged against a neighbour's answer about text that was no longer the one under refinement.

The reviewer's first Must was the kind only a cold read finds: `currentCycle` decided the cycle
from `mine.find(...)`, one row of a read the query's own docstring calls unordered — and one
cycle's rows can carry different baselines, since a round written while the human version held no
such section carries null and a later round carries a hash. Two reads of identical rows could
disagree, one answering `closed` and the next `revise` on cycle 2. It reads every row of the
newest cycle now.

The reviewer's last pass found the one the schema deserved: the rewritten shape constraint said
`surfaced` runs rounds 1 to 3 and nothing about *which* early surfacing is legal, so the table
would have taken a round-1 surfacing on any objection — a loop skipping the cap with the database
not noticing, while `docs/schema.md` still called that constraint the cap in the database. An
early surfacing now has to carry `evidence_truncated` and no author position. It cost one clause
because 0017 is still unapplied; after the apply it would have cost an 0018.

Fifteen database tests skip until `drizzle/0017_refinement_cycles.sql` is applied, and the file's
gate reads the `cycle_no` column rather than only the table, so a database holding 0015 alone
still skips rather than running assertions about a cycle it does not have. That is build-log open
question 40's pattern for the third time, still by precedent and still not by decision.

What is not built is the dock: AC1–AC7 and AB1–AB8, eighteen criteria spanning streaming, agent
states, proposal cards, four responsive modes and a command palette. The report says so plainly
rather than leaving it to be noticed. Guidelines §6 says one task, one session; this ticket is
more than two, and whether the remainder is re-cut is the owner's call.
