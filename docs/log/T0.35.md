# T0.35 — Patch §9: delivery and report-back
_2026-09-23T07:33:00Z_

§9 shipped the constitution "as `AGENTS.md` … plus a `CLAUDE.md` mirror", which is two copies of one
document. The evidence that this costs something is outside the spec, and it belongs here rather
than there: Claude Code today skips `AGENTS.md` by default in any repository that already carries a
`CLAUDE.md`, and reads `AGENTS.md` directly only from v2.1.277; Frame, an open-source spec-driven
IDE, found a root `AGENTS.md` not loading at all on 2.1.247, and one project spending 14% of its
instruction context on a duplicated copy. So the constitution as specified was, in a team repository
with its own `CLAUDE.md`, either invisible or an overwrite of somebody else's file. Those version
numbers are why the ruling exists; they are deliberately not in the spec, because they will be wrong
by the time T5.5 reads it.

What went in instead is three rules and the reason for each. aenima never rewrites, moves or appends
to an instruction file the team owns. It delivers through exactly one channel per repository, never
a copy beside the file it copies — an instruction file loaded twice is context spent twice, and two
copies drift apart. And the channel is chosen at emission from what the repository already carries
and what the team's agent loads today: measured, never assumed. The last clause is the whole point.
A file matrix in the spec would be a snapshot of one week of one vendor's behaviour; a rule that
says *measure it* survives the releases that will break the snapshot. Appendix D's "CLAUDE.md
mirrors the root." became "No mirror — delivery follows §9's rules," which is the same ruling said
once rather than twice.

The second half is the report-back. It arrived in §9 as "completion signal and question intake" —
a phrase, not a shape — while §12's code node law says a transformation describable without the
words judge, decide, assess or summarize must be written as code. A parser cannot be written against
a phrase. So Layer 3's preamble now names six entries in a fixed order, and the closing paragraph
says the thing that makes them parseable: fixed headings, one line per entry, and an entry that does
not parse is shown to a person rather than guessed at. That last clause is the code node law's other
half — where the shape fails, a person reads it; nothing infers.

Among the six is one word the spec did not have. A **departure** is a place the build left the pack,
with its reason. It is read the way an open question already is — evidence against the pack, a
candidate probe, and where the pack itself was wrong, a spec patch the Decider approves. That is
§8's fault attribution arriving from the build side, which is the direction it never had: §8 could
say where a gap lived when a human found one, and had nothing to read when the builder found one.
*Files touched* is the other entry that earns its place: §17's v1.1 wants hook configs that
hard-enforce the ticket fence, and the fence has to be enforced against something. aenima never sees
the code, so the pack asks the builder for the list and never supplies one — now said in §17 rather
than assumed.

One inconsistency is left standing on purpose. Appendix D's constitution skeleton still ends
"Report: ACs implemented, tests written, open questions" — the three-entry shape §9 just replaced.
The ticket fenced Appendix D to its mirror sentence and AC7 forbade touching anything else, so the
reviewer's finding became a Backlog task rather than an edit. That is the fence working: a ticket
that names five places changes five places, and the sixth becomes a ticket of its own.
