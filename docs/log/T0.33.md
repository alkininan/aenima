# T0.33 — Load standing rules by path
_2026-09-23T06:01:17Z_

The rules this build paid for reached a run by memory. `CLAUDE.md` pointed at "References (read on
demand)", the build log's Decisions section ran to about 92,000 characters, and a rule arrived when
the person cutting the ticket remembered it existed. Frame measured that route over its own
transcripts and found the lookup tool its `AGENTS.md` prescribed ran in 18 of 937 searches. Claude
Code has a mechanism that asks nobody to remember: a file under `.claude/rules/` with a `paths:`
frontmatter list loads only when the session reads a file the list matches, and reloads after
compaction. That is product-spec §9's "loaded only when the agent works there", turned on this
repo.

Seven area files now carry the log's standing rules, one rule to a line, each ending in where its
story is — a `docs/log/` path, or a phrase quoted from the Decisions section. Migrations, database
access, the scoring engine, packs, the AI seam, surfaces, tests. Nothing moved out of the log and
nothing came out of `CLAUDE.md`: this is an index, not a restructuring. Forty-seven lines against
ninety-odd bullets, so it indexes the rules and leaves the stories where they are.

An index that can go stale silently is worse than none, so `scripts/rules.mjs` asks the one
question that matters — does every file still resolve? Four ways one stops: no `paths:` list, which
would load it at every launch like `CLAUDE.md`; a glob that reaches no tracked file; a source path
that no longer exists; a quoted phrase the log no longer carries. Each is a test, and each test was
reddened by deleting the branch of `check` that catches it and watching exactly one case fail.

The interesting part was that the guard and the mechanism are two different readers of one string,
and the reviewer went to the binary rather than to the docs to settle what the second one does.
Claude Code loads a rules file by expanding the brace groups itself, dropping a list that
normalizes to nothing, stripping a trailing `/**`, and then matching with gitignore semantics —
not with Node's glob. Three findings came out of that comparison and all three were real: an inline
`paths:` value split on every comma, so `{ts,tsx}` became two patterns matching nothing and the
guard reported a stale glob for a pattern the mechanism expands and matches; a list of nothing but
`**` passed the guard although the binary drops it and the file then loads at every launch, which
is the single thing AC1 exists to refuse; and Node's glob spells a literal bracket `[[]` where
Claude Code spells it `\[`, so the escape the ticket's own Rules prescribe would have been
reddened. The first two are fixed and the escape is translated. What stands is that the two
matchers agree on today's twelve patterns rather than by construction — `ignore` is in the lockfile
and the loader already uses it, so the honest close is to match with it and retire the translation.

The first review pass found the same class of error one directory over: `migrations.md` was scoped
to `drizzle/**`, but the CHECK-passes-NULL and composite-foreign-key rules are about DDL typed in
`src/db/schema/tables.ts`, so a session editing the schema loaded `database.md` and got neither of
the two rules it most needed. A rule that does not reach the code it governs is an index entry for
nobody. The third pass found forty-five tracked files that reach no rules file at all, two of them
files the log has a standing rule about — `surfaces.md` carries the focus-modality rule and does
not reach `src/lib/focus-modality.ts`, the module that rule names. That one is recorded rather than
fixed: three passes is the ceiling, and a change made after the last pass is a change nothing read.
