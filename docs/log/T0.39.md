# T0.39 — Revert only on a wrong answer, never on silence
_2026-09-24T08:59:46Z_

The deploy check asks aeni.ma two questions once per commit of main and reverts the merge at the tip
when the answers are wrong. It also read no answer as a wrong one. On 2026-09-24 the machine running
the schedule could not look the site up; `health.mjs` said down on both attempts, the protocol
called for a revert, and only the run's own judgement declined it — forced to the site's address,
`/sign-in` gave 200 and `/app` gave 307. A merge cannot break a name lookup, so silence is no
verdict on one.

`assess` now has three outcomes. **Up**: every check answered as expected. **Down**: a check
answered with the wrong status, whatever the others did — that alone reverts, and the commit is
recorded so one outage reverts one merge. **Unknown**: a check never answered and none answered
wrongly — nothing is reverted, filed or recorded, and the next run asks about the same commit again.
The old `ok` flag went with it: a boolean over three outcomes had one value meaning two things, and
the skill now branches on `outcome` alone. The deploy window's wait reports no outcome, since it
asked nothing. Guidelines v1.28 and the skill's step e say the same.
