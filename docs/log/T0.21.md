# T0.21 — Merge by default
_2026-09-16T10:10:00Z_

T0.16 gave the pipeline the right to merge its own work and then took three kinds of change back
out of it: a migration, the product spec, and anything under `.claude/`, `scripts/hooks/` or
`scripts/run/`. Two of those three were ceremony. The human owns a spec upstream, in the
conversation that cuts the ticket — re-approving the diff a week later adds nothing anyone would
act on. And a harness diff is not dangerous because of where it lands. A new script is a harness
diff; so is a reworded comment; so is deleting the rule that refuses `drizzle-kit push`. Gating by
path treated all three as the same risk, which is a way of saying the risk was never measured.

**So this ticket measures it.** `scripts/run/loosening.mjs` extracts `scripts/` from both sides of
the diff and runs the restraints themselves — the guard's `decide()`, `gated.mjs`'s
`isGatedPath()` — against one fixed corpus, a side to a child process, and asks one question:
is anything refused before allowed after? That is an answer with a mechanism behind it rather
than a judgment, which is the whole point. A rule deleted shows up as two corpus commands going
from refused to allowed. A matcher narrowed shows up as one. Nothing about the shape of the diff
is read anywhere in it. The corpus is always `origin/main`'s, because the hooks run main's copy,
so a diff cannot grade its own paper; the price is that adding a guard rule is gated until the
corpus grows to cover it, and that price is the rule the ticket asked for.

**The three reviews were where the ticket actually got built.** Each pass found a hole of the same
shape — something load-bearing that the measurement did not reach — and none of them were
arguable. Pass 1: the gate's commands are `package.json`'s, not `STEPS`, because the gate spawns
`pnpm <step>`; a `"test": "true"` left `STEPS` three long and the suite toothless. Pass 1 again:
`hooksOf` kept one command a group, and `SessionEnd` holds two, so deleting `release.mjs` was
invisible. Pass 2: `git diff --name-only` prints a rename's destination alone, so `git mv`-ing the
detector took it out of its own check — the file that cannot mark its own homework could be
replaced wholesale by a self-merging diff. Pass 2 again, and this is the one that mattered most:
the guard's rule table only *reacts* to the two doors a merge and a close rest on. `reviewed()`
decides whether a PASS opens a merge and the gate's `decide()` decides whether a red suite can
close, and both were injected as fixed refusals in the corpus, so a diff that made either answer
yes to everything would have self-merged — and from main, the gutted copy would have judged every
diff after it. `DOOR_CORPUS` closes that. Pass 3 found the last inch of the same thread: every
door entry handed `reviewed` a diff, so the line that computes one when nothing does, and
`gatedDiff`'s `...weakened` spread behind it, still sat outside the measurement.

That last fix landed after the third and final pass, so it carries no cold verdict, and the
verdict file reads FINDINGS. It costs nothing here: this diff edits the detector, so it is gated
on its own rule and waits at Review for the word — the last pull request that needs one, which is
what the ticket said it would be.

Two gaps stay open and are recorded rather than quietly taken. `.worktreeinclude` and `.gitignore`
came out of the gated set and nothing measures them, so a diff appending `.env.migrate` to the
first would hand every worktree the admin credential; guard rule (b) is still the layer that
refuses the migration itself, so this is a second layer gone rather than the boundary. And
`CRITERION` is not ticket-scoped: a deleted test naming `AC1` reads as replaced by any added file
naming `AC1`, and every ticket has an `AC1`.
