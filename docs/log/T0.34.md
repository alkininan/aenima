# T0.34 — Check claims at Inline, file rules
_2026-09-23T07:12:40Z_

A ticket is cut in chat, away from the code. Every backticked name in it — a script it says to
edit, a function it says to call — is a claim about a repository nobody looked at while writing it,
and nothing checked them. `spec-sections.mjs` catches a cited *section* that has moved; a cited
*name* that has moved surfaced in review, or not at all. Frame's planner puts this first: every
claim in a spec is checked against the code before a word of plan is written, each one confirmed or
marked drifted. Step 2 does that now, with `scripts/run/claims.mjs`.

The script finds names and stops there. Paths resolve as files against `origin/main` — never the
working tree, which can be ahead of it — and identifiers go through a word-bounded `git grep`;
commands, flags, placeholders, globs, numbers and code fragments are never looked up at all. What an
absent name *means* is the skill's, because only a reader of the ticket can tell a file the ticket
is about to create from a file that moved. That is §12's code node law with the boundary drawn at
the place the two kinds of knowledge actually part.

Three review passes, one Must each, and all three were the same defect wearing different clothes:
the answer was right for the shape the ticket that wrote it happened to be in. A bare `log-index.mjs`
was looked up at the repository root alone, so 41 files main tracks read as missing. An `## Addendum`
written below `## Cited` was thrown away with the quotation, so the freshest names in the file went
unchecked — in the round step 2 names in the same breath as this check. And the fix for that one
resumed the ticket at the next `## ` heading, which on an unfenced cited section is a heading of the
quotation: T0.12's `## Cited` is followed seven lines later by `## 2. Databases`, and the sweep over
`docs/tickets/` went from 9 absent names to 42. Only `## Addendum` resumes it now. The measurement
that settled each of the three was the same one — run the script over all 36 ticket files and read
what it says — and it is the measurement that should settle the fourth.

The third Must was fixed after the three-pass cap, so no cold reading has seen it. The verdict on
file says `FINDINGS` and the ticket waits at Review rather than merging on the run's word, which is
what the cap is for.

The other half of the ticket is step 8. A rule a ticket established used to reach a later run only
if somebody cited it; with T0.33's area files loading by path, step 8 now files one as a line in
`.claude/rules/<area>.md` ending in the ticket's own log entry, and a rule that binds everywhere
goes to the report's open questions rather than into `CLAUDE.md` — that file is the contract and
the edit is the human's. Nothing under `.claude/rules/` reached `scripts/run/**` before this, so
the instruction had no destination for a harness rule; `harness.md` is the first, written by this
ticket using its own step 8. §6 gained the other side of it: a ticket's Rules section carries only
what is not already standing, because a rule restated in a ticket is a second copy that can
disagree with the first.
