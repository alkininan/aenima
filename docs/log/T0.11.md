# T0.11 — Comments: a comment on the board is enough
_2026-09-13T20:05:00Z_

T0.11 — comments. Every run now reads every task's thread over the Notion API in one command
and gives each reply the pipeline has not answered exactly one assessment: a change at Review
is folded into the body and sent back to Ready on the same branch and pull request; work beyond
the ticket becomes one Backlog task drafted from the reply, linking back; an answer resolves a
Decision; and the two words with consequences, `merge` and `apply`, are verified by the guard
itself — the marker names the task, the integration token opens the board, the human's newest
reply must begin with the word at the state the word is for, and a merge must be the task's own
branch as the board names it, merged with a merge commit. The model never asserts a permission.
`claim.mjs` refuses to land on a live run's marker, `branch.mjs` reuses a branch already on
origin and frees the worktree that held it, and an idle run may file one Fix task when its own
preflight went red. Guidelines v1.6, build-guide v2.5. Three review passes; pass 3's Musts were
fixed after the cap and wait for a cold read. The live cycle waits on the human step: a Notion
internal integration and `NOTION_TOKEN` in `.env.local`, said on the board row.
