## Open questions

1. **§3's Latin Extended preload waits on per-request locale resolution — owner: the phase that
   resolves a locale (Phase 6, onboarding and roles, where `src/i18n` stops being one dictionary).**
   §3 asks for each face's Latin subset preloaded "and its Latin Extended subset too when the locale
   is TR or NL". The first half ships. The second cannot be written today for two reasons that meet:
   the font compiler reads `preload` out of the source, so it must be a literal and cannot ask which
   locale is rendering; and nothing renders TR or NL — `src/i18n` holds `en.ts` alone and
   `getDictionary()` takes `DEFAULT_LOCALE`. So the Latin Extended subsets are declared with their
   own `unicode-range` and not preloaded, which is exactly §3's rule for EN, and a Turkish letter
   fetches its file on demand. When a locale is resolved per request this becomes a per-locale entry
   point — two font modules, or a route group per locale — rather than a flag on these calls.
2. **`--delay-tooltip` is a CSS token and the tooltip's delay is a `setTimeout`, so 500 lives
   twice.** §6 puts the delay in the CSS block, but `Tooltip.tsx` opens on a timer, and
   `variants.ts` holds `TOOLTIP_SHOW_DELAY_MS = 500`. It cannot move into `motion.ts`: that module
   holds §6's script timers and no other, and this is not one of them. Whoever brings the tooltip to
   v2.21 decides which of the two is the source — a CSS `transition-delay` that reads the token, or
   a script timer §6 names as one.
3. **C-39's "no component sets `font-size` or `line-height` as a literal" is not checked here.** No
   component does today outside the type scale itself, but `globals.css`'s floating label sets both
   as literals in two states, deliberately: §8 animates the label's size between `ui-label` and
   `ui-input`, and a class cannot be transitioned. Naming those two numbers as tokens would put
   values in `globals.css` that the document does not declare, which C-05 forbids. Left to *Design
   law checks* (C-06), which owns component literals and can decide the two together.
4. **The two vendored faces ship without a metric-matched fallback.** `next/font` generates one per
   call, named after the call rather than after the family, so the two subsets of one face generate
   two; `globals.css` names the family itself — `'DM Sans', system-ui, sans-serif`, §3's own value —
   and reaches neither. The faces are preloaded and `font-display: swap`, so the gap is the swap
   itself. If it shows, the fix is one `@font-face` for the fallback family, written beside the
   token rather than generated.
