The first call of pass 1 went to `fable`, the model `.claude/agents/reviewer.md` pins, and came
back an API error rather than a review — out of usage credits. `review-model.mjs` read that as
`credits`, so the pass ran again on `opus`, the next model of the chain, in a fresh session with
the same one-line message. Pass 3 stopped at its 30-turn limit with no verdict, was resumed once
and finished.

**Pass 1 — one Must, six Shoulds.** The Must: a token was looked up as a path relative to the
repository root and nowhere else, so a backticked bare file name — the way this repo's tickets
usually name a script — came back absent although main holds the file one directory down. Measured
over the 36 files in `docs/tickets/`: 51 absent entries, at least 41 of them naming a file main
tracks. Fixed by matching a slash-less token on the reference's file names as well as at the root;
a name with a slash must still resolve as a path. Shoulds 1, 2, 4 and 5 were taken as well — an
unreadable reference now says so rather than answering that every name is drift, `git grep` runs
word-bounded so `unScorer` no longer reads as present from the line holding `runScorer`, both
header entries say which version numbers the open branches hold, and the build guide's title line
caught up with its header. Should 2's second half — narrowing the grep to code with a pathspec —
was not taken: a name that appears only in a document is still in the repository, and a ticket
naming one is not making a false claim. Shoulds 3 and 6 are below.

**Pass 2 — one Must, four Shoulds.** `ownSections` kept the head of the file and threw the tail
away, so an `## Addendum` written below `## Cited` went with the discard — two of the seven ticket

looked up. That is the half of AC1 that says *every*, failing silently, in the round §5 step 2
names in the same breath as this check. Fixed by cutting the Cited section out rather than reading
only what is above it. Two Shoulds taken: the guidelines header said "v1.21 and v1.22 are held by
open branches" when what is true is that two open branches both hold a v1.21, and TC7's split on a
bare version number cut the entry short at its own prose.

any kind, and most cited sections on main are pasted *unfenced*, so that heading is a heading of

## Open questions

1. **Pass 3's Must is fixed and no review pass has read the fix** — owner `T-next`. Three passes is
   the cap, and the correction landed after it. It is the one-line rule the third pass itself
   named, it is covered by two TC1 cases, and the sweep over every ticket file on main is the
   measurement; none of that is a cold reading of the diff. The verdict file says `FINDINGS`, so
   the ticket waits at Review for a human's word rather than merging on the run's.

2. **`classify`'s scope came from measuring the corpus, and a count says what the documents that
   exist contain rather than what the next one will.** Every rule in it was chosen against the 36
   files in `docs/tickets/` — that is the right way to choose which shapes are worth handling and
   the wrong way to establish that a shape is safe, which is the lesson the build log already
   carries about the evidence guard's markdown fold. What the measurement cannot see: a ticket that
   introduces a new top-level directory names a path whose first segment is not yet in the
   reference and which carries no extension, and it is skipped rather than reported. That is the
   conservative direction — a missed name, never a false one — and it is written down here so the
   next person widening this brings a count rather than a guess.

3. **A name that exists only in prose reads as present.** The identifier lookup is word-bounded but
   searches the whole reference, documentation included, so a function deleted from the code and
   still named in a report answers `present`. Narrowing to code with a pathspec was the reviewer's
   suggestion and was not taken, because a name in a document is genuinely in the repository and a
   ticket citing one is making a true claim. The case this misses is a rename whose old name
   survives in the build log — which is most of them. Decide it the first time a real rename slips
   through; the trigger is a drift the step should have caught and did not.

4. **Nothing in `.claude/rules/` reached `scripts/run/**` before this ticket**, so step 8's new
   instruction had no destination for a rule about the harness — most of phase 0, this ticket
   included. `.claude/rules/harness.md` is written here as the first one, and it is this ticket
   using its own step 8. Whether the rest of phase 0's harness lessons belong in it is a sweep
   somebody should make deliberately rather than a thing to do in passing.
