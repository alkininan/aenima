## Open questions

1. **The guard matches raw command text.** During T0.98 the guard refused the Bash heredoc that
   first wrote `scripts/run/README.md`, because the README's step 6 named the migrate command
   literally; the file went in through the Write tool and the sentence now says "the migrate
   command". The same refusal hit this close: the report you are reading names the command in
   this very item, so it was written with the Write tool, not a heredoc. A guard that reads a
   command string cannot tell a mention from an invocation. T0.7's open question 36 named this;
   T0.8 was its owner and did not settle it. Owner: T0.9, or a Fix task under E0.2.
2. **The parallel gate and reviewer suites redden `SignInForm.dom.test.tsx`.** Two cases
   (`reachCodeStep`, `findByRole` at its default timeout) went red under the full parallel
   `pnpm test` — once for the reviewer, once for the Stop gate — and pass 20/20 alone. The Stop
   hook runs the suite exactly that way, so a red there can refuse a close the ticket did not
   cause. Filed by T0.98's run as a Backlog task, Type Fix, Epic E0.2. Owner: that task.
3. **Reviewer 529s need stale-run handling.** The reviewer subagent hit provider 529s during
   the fixture runs. A reviewer that dies mid-step-5 leaves the task at In progress, and the
   next run's preflight (c) then reports "a run is in progress" and claims nothing until a
   human resets the row. Stale-run detection is T0.9's by the ticket; the 529 is the concrete
   case it must cover, and a retry on 529 before the run gives up is the cheap half. Owner: T0.9.
4. **Headless `claude -p` has no connectors, so the scheduler must be a Desktop task.** The
   skill reads and writes the board through the Notion connector, and a headless `claude -p`
   session does not carry connectors. The ticket's live tests were specified as `claude -p
   "/ticket"`; the runs that reached the board did so from a Desktop session. T0.9's scheduled
   run therefore has to be a Desktop scheduled task, not a cron'd `claude -p`. T0.7's open
   question 37 (`--fallback-model` is `--print`-only) has to be re-read against that session
   mode: `fallbackModel` in settings must be confirmed to fire there. Owner: T0.9.
5. **`gh pr merge` is not guarded.** Rule (d) refuses `git merge` with main checked out and any
   push that names main; `gh pr merge --merge` writes main through the API and passes the guard
   from any branch. Guidelines §5 says "never merge" and calls the merge the human's move; the
   hook does not enforce it for `gh`. This close used it, on the human's instruction. Owner:
   T0.9, with the guard.
6. **TC1–TC6 have no recorded red-first observation, and TC10 no live observation.** The tests
   pass and carry their `TCn → ACn` markers; the per-mutation record the ticket's Done section
   asks for was never written. Re-running the mutations against `main` is a bounded task.
   Owner: a Fix task under E0.2, if the record is wanted.
7. **The skill and §5 disagree on where the commit goes.** `SKILL.md` step 8 commits on the
   branch and step 9 pushes; §5 lists commit under 9 Close. T0.98's reviewer found it (pass 2,
   finding 2) and filed it. Owner: that task.
