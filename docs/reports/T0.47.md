# T0.47 — Confirm the deploy check reads Vercel

The deploy check now asks the deployment's public address, `https://aenima-puce.vercel.app`, after
`https://aeni.ma`, and reads an answer's status only once Vercel's own headers say the answer is
Vercel's. `isVercel(response)` in `scripts/run/health.mjs` — `server: Vercel`, compared whole and
case aside, or a non-empty `x-vercel-id`; either suffices, both are set by Vercel's edge — sits
between the login recognition T0.43 added and the status read. An answer that is neither the login
nor Vercel's is kept as `{ path, expected, status: null, elsewhere: true, returned }` and not asked
again: no answer from that address, so `assess` reads it unknown and never down, `answered` moves
`health` on to the next address, and `describeTried` names it in the report line —
`/app answered 200 without Vercel's headers`. That is how a parked aeni.ma stops hiding the
deployment. The team-only alias `aenima-ae-nima.vercel.app`, behind Vercel's login and so blind
from outside since T0.43 merged, leaves `.claude/board.json`; `isVercelLogin` stays byte for byte,
since Vercel's login carries Vercel's headers too and the header check confirms the platform, not
the project. Guidelines v1.32, its step-0 row and `scripts/run/README.md` say so; `health.mjs`'s
header and `.env.example` no longer say the deployment's address is behind a login; nothing under
`src/` changed and `e2e/production.spec.ts` is untouched.
