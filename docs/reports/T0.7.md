## Open questions

1. `$CLAUDE_PROJECT_DIR` vs `cwd` as the gate's working directory — settle as a rule before T0.8
   puts tickets on branches. Owner: T0.8.
2. `.worktreeinclude` carries no `.claude/settings.local.json`, so a worktree session has no
   Supabase MCP. Owner: T0.8, if worktree runs become the norm.
3. `.env.example` is refused by rule (e) because the ticket says `.env*` without a carve-out; it
   holds no secret and `.gitignore` already treats it as the exception. Owner: T0.8.
4. Rule (e) covers redirects (`>`, `>>`, `>&`, `>|`), `tee`, `cp`/`mv`/`install`, `sed -i` and
   `--in-place`. Still reaching `.env*`: an exotic writer (`python -c`, `dd of=…`, `truncate`,
   an editor), a subshell-grouped command (`(git push --force)` — the first word is `(git`),
   a redirect quoted inside `sh -c '…'`, and `sed -i --expression=… .env.local` (no script
   operand, so the file is dropped as one). Rule (d) likewise reads only `-C`/`-c` as
   value-taking git options; `--git-dir`, `--work-tree`, `--namespace` and `--config-env` also
   take a value, so `git --git-dir .git push --force` is allowed; and only `env`/`command`/
   `exec` are stepped over as wrappers, not `sudo`, `time`, `nohup` or `nice`. The tokenizer
   was built to find write targets, not to be a shell; the line between growing it and
   stopping is T0.8's. Owner: T0.8.
5. The `reviewer` subagent type registered mid-session after the first `claude -p` run, not
   immediately on file creation. `claude -p --agent <name>` from Bash is a genuinely fresh context
   either way. Worth a line in the build guide if it recurs.
6. Rules (a)–(d) read the Bash command text, in both directions. A script file that contains
   `drizzle-kit push` and is run as `bash file.sh` is not refused; neither is a `package.json`
   script whose name does not contain the words. And a *read* whose text contains the words is
   refused — `grep -n "db:migrate" scripts/hooks/guard.mjs`, `git log --grep=db:push` — which is
   how this ticket's own mutation script was refused before it was moved into a file. The ticket
   asks for "containing … always" and got it; closing either direction needs a rule about what a
   hook may inspect. Owner: T0.8.
7. `--fallback-model` is documented in `claude --help` as "(only works with --print)". If the
   `fallbackModel` settings key has the same scope, "Fable falls back to Opus on outage" holds
   only for headless runs — which is what guidelines §5's scheduled run is, but T0.8 decides the
   session mode and should confirm the fallback fires in it. Owner: T0.8.
8. Rule (d) reads the branch of the hook's `cwd`. For `git -C <path> merge …` the checkout that
   matters is `<path>`; the guard refuses when `cwd` is on main and lets it through otherwise,
   which is the ticket's rule applied to the wrong directory in that one shape. Owner: T0.8, with
