## What the docs said that changed the pack's shape

Read on 2026-09-09 from code.claude.com, not from memory.

1. **A worktree is a toggle, off by default.** "By default, scheduled tasks run against whatever
   state your working directory is in … Enable the worktree toggle when creating the task to give
   each run its own isolated Git worktree." `.worktreeinclude` applies to Desktop sessions, so
   `.env.local` is carried. The task runs with the toggle on.
2. **Permission mode, model, folder and the worktree toggle are form-only.** The create tool a
   session can call takes a name, a prompt and a cron expression; the task directory holds only
   `SKILL.md`. The human sets the four fields in Routines › Edit.
3. **Bypass, not Auto.** "Never prompts" is Bypass permissions. Auto "reduces" prompts and runs a
   classifier, which refused this session's read-only probe; a refusal inside an unattended run
   is a wasted hour. Approved at plan.
4. **Desktop already refuses to overlap runs of one task.** Run history marks a run skipped when
   "the previous run was still in progress". The shared marker covers a `/ticket` typed by hand
   meanwhile.
5. **Desktop does not remove a run's worktree.** A worktree goes with its session's archive, by
   hand or by auto-archive after a merged pull request; an idle run opens no pull request. Hence
   `prune.mjs`.
6. **"Physically cannot" is too strong.** Worktree isolation blocks edits and git into the main
   checkout, not file reads. §5 says what the boundary is: the credential a run is handed cannot
   change schema, and the admin credential is on no path a run follows. Rule (b) stays.
7. **A plain DML role cannot run the suite.** Every public table has RLS forced and every policy
   is `TO authenticated`; Postgres 17 lets no non-superuser grant BYPASSRLS. The role is a member
   of `service_role` and starts every connection as it (`alter role … set role`), which the
   catalogs confirm: `rolconfig = {role=service_role}`, and a connection reads
   `session_user = aenima_pipeline, current_user = service_role`.
8. **`service_role` holds no privilege on `auth.users`**, and `postgres` can grant only SELECT
   there. Migration `0014_test_users.sql` adds `app.seed_user` and `app.delete_user`, definer
   functions owned by `postgres` with execute for `service_role` only; eight db test files call
   them. Approved at plan; applied by the human.
9. **No Vercel CLI, no login files on the machine.** Nothing to log out. Rule (c) stays.

## Defaults taken under §4

- **A dirty stamped worktree is skipped, never forced.** `git worktree remove` refuses it and the
  run says so; a person looks. Nothing forces.
- **The log entry's commit is optional and a run leaves it off**: the board row holds the commit,
  and the hash is not known until step 9 commits.
- **The migrated entries are dated by their closing commit**, the last one each entry names,
  except where the entry named a later addition (T2.3 → `19a079f`, T0.8 → `7136df3`) or none
  (T2.7 → `6e0cc56`, T2.4 → `9e4371a`, Deploy → `9b3ac04`, the build-log commit that recorded it).
  The list is chronological by that timestamp, so T2.4 and T2.6 now sit before T2.5 where the
  old file had T2.7 before T2.4.
- **The six `###` subsections became sections of their tickets' files**: T2.4's rulings and
  review into `T2.4.md`, T2.5's three into `T2.5.md`, the golden set's first labeled sample into
  `T2.3.md`.
- **`0014_snapshot.json` was not kept.** `drizzle-kit generate --custom` wrote one; no custom
  migration since 0002 has a snapshot, and this one changes no DSL schema.
- **`grant usage on schema app to service_role`** widens nothing a client can reach: PostgREST
  exposes `public`, and `service_role` already bypasses RLS.
- **`next typegen` joins the install in step 0** rather than the `typecheck` script or the gate:
  the route types are a worktree's missing artefact like `node_modules`, and preflight is where
  a run tends the ground it stands on. A developer surface; one line; §4's default.
- **Bootstrap's no-identity test covers both real callers** rather than the owner with no JWT,
  which no production request is: `anon` is refused by privilege, `authenticated` with no subject
  by the function's own check.
