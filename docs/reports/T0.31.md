# T0.31 — Read bundled shell -c flags

`parse()` in `scripts/hooks/guard.mjs` reads the command string of `sh -c "…"` as the commands it
runs, and it looked for the flag as a bare word. Short flags cluster in one word, and every shell
the guard knows reads a `c` anywhere in that cluster as `-c`: `bash -lc '…'`, `sh -ec '…'`,
`bash -xc '…'` all run the next word, and so does `bash -cl '…'`. Read as text a cluster is not
`-c`, so the word it ran was hidden from every rule below. On main that carried `pnpm db:push`
past rule (a), `git push --force` past rule (d) and a write to the board's API past rule (i) —
and, as the reviewer measured, rules (b), (c), (e) and (f) with them.

One predicate now answers what the flag is, used at both sites that looked for the bare word:
`parse()`, which expands the string into the commands it runs, and `shellRun()`, which skips a
shell carrying `-c` because `parse()` has already read it. Two corrections came out of review,
both of them the same mistake in opposite directions — a matcher that reads a word as the flag
when it is not one, and a search that looks for it where it cannot be. `shellRun` scanned the
whole tail, and the tail holds the script's own arguments, so `bash post.sh -lc` stopped the file
being read at all; only the words before the first operand are the shell's. And bash spells its
long options with one dash as much as two, four of which are a run of letters holding a `c` —
`-norc`, `-rcfile`, `-restricted`, `-protected` — each of which read as a cluster and shadowed the
real `-c` behind it. Those four are named, and `parse()` follows every word that reads as the
flag rather than the first, so an option nobody named still cannot stand in front of a real `-c`.

**Pass 1, Must 1 — `shellRun` stopped reading scripts it used to read.** `rest.some(isCommandFlag)`
scanned everything after the shell's name, the script path and the script's own arguments
included, so a flag-looking argument hid the file: `bash post.sh -lc` and `sh post.sh -vc extra`,
with `post.sh` writing the board, were refused on main and allowed at `574d3c4` — `readScript` was
never called. Fixed at `3ffeb87`: the cluster is looked for among the words before the first
operand alone. The reviewer noted `parse()` has the mirror of this, `findIndex` over the whole
tail, and suggested the same shape there; it was left as it was, because at that site reading a
word that is not a command string parses one more command line, which refuses more and never
less. Narrowing it would have been a loosening.

**Pass 2, Must 1 — a one-dash long option read as a cluster.** Bash accepts `-norc`, `-rcfile` and
`-restricted` in the one-dash spelling — all three verified by running them — and each is a run of
letters holding a `c`, so the matcher took it for `-c` and `findIndex` stopped there. Measured,
`bash -norc -c 'pnpm db:push'`, `… 'git push --force'` and `… "curl -X POST …/v1/comments"` were
refused on main and allowed at `3ffeb87`, rules (a), (d) and (i); `bash -norc post.sh` went unread
through the second site; and the ticket's own `bash -norc -lc '…'` lost to the same word. Fixed at
`7ec8dd6` with the named set and, behind it, `parse()` following every match rather than the first.

**Pass 3 — PASS, four Shoulds.** The reviewer measured `origin/main`'s `decide()` against this
commit's over 6,382 shell shapes: 588 transitions, every one allowed → refused.

- **Should 1, fixed after the verdict.** `ONE_DASH_LONG` named three of bash's letters-only long

## Open questions

- **A default taken, cheap to change.** AC1 says *bundled short flags ending in `c`*. Every shell
  in `SHELLS` reads a `c` anywhere in the cluster — `bash -cl '…'` runs its string as surely as
  `bash -lc '…'` does, which I ran rather than assumed — so the matcher reads the whole cluster
  and not only its last letter. Reading only a cluster that ends in `c` would have left the same
  hole one letter away. This is a developer surface and one regex, so it was taken rather than
  stopped on; say the word if the narrower reading was meant.
- **`loosening.mjs`'s corpus holds no bundled shape.** Every refused → allowed transition found in
  this ticket — pass 1's Must, pass 2's Must, pass 3's Should 1 — was invisible to
  `scripts/run/loosening.mjs`, which answered `ok: true` throughout while the guard's rule (i) was
  open. The reviewer measured each by running both sides itself. A corpus entry per bundled shape
  would put that measurement where the close reads it rather than where a reviewer happens to look.
