## Defaults taken under the new §4

Each cheap to undo, each said once here rather than stopped on.

- **SessionEnd is the trap.** It is the only hook the runtime fires on termination; it cannot
  block, which is fine for cleanup. A hard kill fires nothing, which the three-hour age covers.
- **The reviewer runs only the named tests** — not lint, not typecheck. Both are the gate's.
- **Recovery commits a dirty tree onto the stale branch** before renaming, and renames a pushed
  copy on origin the same way, so salvage is complete.
- **Several stale tasks:** each recovered and commented; `pick-next` orders them, the first is
  re-claimed, the rest return to Ready (§3 gained that row).
- **Guard rule (b) names T0.10** as the owner of the answered-migration path; the test that
  pinned "T0.8" now pins "T0.10".
- **Build-guide's three stale lines** (§2 twice, the hooks paragraph) patched, v2.2 → v2.3;
  guidelines §2, §5 and §8 now say T0.10 where they said T0.9.
- **The parser reads `$(…)`, backticks and `sh -c "…"`** as nested commands and steps over
  `sudo`/`time`/`nohup`/`nice` — a few lines past the ticket's list, in the direction that
  refuses more, and build-log open question 34 says where it stops.
- **`<HHMM>` is UTC**, as every stored timestamp is (CLAUDE.md).
- **T0.9's board row stayed at Backlog until close.** A row at In progress with no marker is
  what the fixture tests, and the fixture run must not recover T0.9 from under itself.
