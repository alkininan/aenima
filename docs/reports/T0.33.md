# T0.33 — Load standing rules by path

`.claude/rules/` is a Claude Code mechanism that does not depend on anyone remembering: a file
there with a `paths:` frontmatter list loads only when the session reads a file the list matches,
and reloads after compaction. Seven area files now carry the build log's standing rules, one rule
to a line, each ending in where its story is. `scripts/rules.mjs` is what keeps them true.

The four helper describes named no criterion.

**From pass 2** — an inline `paths:` value split on every comma, so `{ts,tsx}` became two patterns
that match nothing; Claude Code's own parser splits at brace depth zero and this one now does too.
A `paths:` list of nothing but `**` passed the guard, though the binary drops such a list and the
file then loads at every launch, which is exactly what AC1 refuses. Two rule lines quoted the
build log's *Open questions*, the section rewritten when a question closes, where Build step 1 asks
for Decisions: one re-quoted from Decisions, one repointed at `docs/log/T2.1.md`. Every quoted
source now sits in Decisions.

**Standing from pass 3**, recorded rather than fixed — three passes is the ceiling, and a change
made after the last pass is a change nothing read:

1. `dropBlanket` catches a list of literal `**` and nothing else. `paths: ["**/*"]` or `["*"]`
   loads at every launch under the loader's matcher while `check` reads it as sound. The binary
   normalizes first and then asks whether what is left is all-`**`; asking instead whether every
   surviving entry matches an arbitrary path would close all three spellings.
2. Forty-five tracked source files reach no rules file. Two are files the log has a rule about:
   `surfaces.md` carries the focus-modality rule but does not reach `src/lib/focus-modality.ts`,
   the module that rule names, and nothing reaches `src/lib/stage.ts`. `src/lib/authoring/**` and
   `scripts/run/**` are uncovered the same way.
3. The guard resolves a glob with Node's `globSync`; the mechanism resolves it with gitignore
   semantics over the same string. They agree on all twelve committed globs and `toNodeGlob`
   patches the one escape they spell differently, but that is a fact about today's twelve patterns
   rather than a property. `ignore` is already in the lockfile.
4. Four rule lines end in a quote that starts mid-sentence — `"is not the focus split."`,
   `"is the only division in the product"`. A log edit that keeps the predicate and changes the
   subject leaves the guard green on a rule whose source no longer says it.

## Defaults taken

The ticket fixed the mechanism and the areas, not the syntax. Four choices were mine, all cheap to
change — none touches the schema, a route, product copy or an API shape:

- **A quoted source is matched with whitespace folded.** The build log is hard-wrapped, so a
  literal comparison would reject every phrase that crosses a line break, which is most of the
  useful ones. Both sides are flattened before comparing. This is the fold T2.3's evidence guard
  already makes, for the same reason.
- **The rule-line grammar.** A line is a top-level list item ending in ` — ` and then either a
  backticked `docs/log/*.md` path or a double-quoted phrase. The separator is the last em dash on
  the line, so a rule sentence may carry its own.
- **A seventh area, `surfaces.md`.** Build step 1 lists six expected areas and says the areas come
  from the log; the log carries standing rules about `src/app/**`, `src/components/**` and
  `src/i18n/**`, so they got a file.
- **`toNodeGlob`.** The ticket's Rules prescribe `\[key\]` for a literal bracket, which is Claude
  Code's spelling; Node's glob spells it `[[]`. A guard that reddened the escape its own ticket
  prescribes would send the next rule-writer toward a pattern the mechanism cannot read.

## Open questions

1. **`dropBlanket` recognises one spelling of "everything" out of three** — pass 3's first Should,
   above. `["**/*"]` and `["*"]` both load at every launch while the guard reads them as sound.
   Owner: `T-next`.
2. **The index has holes, and two of them are files the log has a rule about** — pass 3's second
   Should. `src/lib/focus-modality.ts` and `src/lib/stage.ts` reach no rules file, and
   `surfaces.md` names the first in a rule it cannot deliver there. This is the same shape as pass
   1's finding about `src/db/schema/**`, one directory over; whoever closes it should decide
   whether `surfaces.md` widens to `src/lib/**` or the uncovered areas get their own files.
   Owner: `T-next`.
3. **The guard's matcher and the mechanism's are two matchers that currently agree** — pass 3's
   third Should. Matching with `ignore`, which the lockfile already carries and the loader already
   uses, would make the guard answer the question the mechanism asks and would retire `toNodeGlob`.
4. **A quote fragment anchors on a predicate** — pass 3's fourth Should. Four lines quote from
   mid-sentence, so a log edit that changes the subject leaves the guard green.
5. **`docs/log/T0.31.md` is stamped 2026-09-23T06:58:00Z, which was still in the future when
   this entry was written at 06:01:17Z.** Noticed because `log-index.mjs` sorts oldest-first by
   stamp and put T0.33 above T0.31, leaving **Newest entry** pointing at T0.31. The index is
   generated correctly from the stamps it is given; the stamp is the thing that is wrong, and it
   is a merged entry's, not this ticket's. It self-corrects within the hour. Not filed on the
   board: a one-line correction to one log entry is cheaper than the row it would take.
6. **The Decisions section's opening line claims more completeness than the index has.** 47 lines
   are indexed against roughly 95 top-level bullets. Build step 4 prescribed this wording and the
   diff wrote what it was told; the next writer may read it as finished. Raised by pass 1 and left
   as written, because rewording the ticket's own prescription is not a run's call.
