## Defaults taken under §4

Posted as this claim's one `default` comment on the task, before step 4's rule held it to the
close (the rule came from pass 1, after the comment was up):

- **AC5 read with AC1.** Every clarifying round answers a reply, so a reset on every reply would
  never let the cap silence anything. A reply resets the count once the run has answered it as
  anything but unclear; the replies between rounds do not.
- **The tag is the words.** Each kind is read back from the fixed words of its own sentence, not a
  visible label — §4's comments carry no labels — which also reads the comments already on the
  board, T0.13's included.
- **Once per claim, on the claimed task's thread, from the claim's start.** Comments on a page no
  claim names — step 0's assessments, step 1's notices — are already one per reply and once per
  thread by their own rules.
- **`threads.mjs` says `clarifyingRounds` and `mayClarify`**, not `mayPost`, so nobody reads the
  flag as covering every comment again; `mayPost` is the function, in `comments.mjs`.
- **A thread the guard could not read holds back a clarifying round and posts everything else.**
- **A claim that could not go on** is `branch.mjs` answering `ok: false`: one `refused` comment,
  release, Decision.

## Open questions

1. **AC5's words and the build differ**, as above: a reply resets the count only through the
   run's answer to it. If "a human reply resets it" meant every reply, the cap never binds and
   AC1 cannot hold. Owner: the human at Review, whose `merge` this gated diff waits for.
2. **A ⟡ comment no composer wrote is neither counted nor capped** (pass 2, Should 5), and a kind
   whose sentence changes on a branch reads as no kind to main's guard until it merges: a
   clarifying round in other words would escape the cap, and any unplaced comment is held to once
   per claim as "a comment no composer wrote". Refusing unplaced comments outright would close
   that, and would also refuse a run's own `gated` or `refused` comment whenever its sentence was
   changed on the branch being closed — the report the cap must never stop. Every change to
   `comments.mjs` is a gated path, so the human sees it first. Owner: E0.2, if a comment is ever
   seen posted outside `compose`.
