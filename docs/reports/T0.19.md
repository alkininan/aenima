## Defaults taken

One, and it is in the diff for the human to see at `merge`. The ticket says to name the three
words; the product spec has no v1 mechanic for two of them — v1 ends at handover, and §11 already
says completion is read back rather than driven. Leaving *apply* and *merge* unattached would have
put two words with consequences into the spec with nothing behind them, and inventing a v1 meaning
for them would have been scope the ticket does not carry. So they are bounded by the language the
spec already holds: §17's "once aenima itself drives a coding agent from the backlog", which it
puts at v2. The header line carries the same split — "*ready* in v1, *apply* and *merge* once
aenima drives a coding agent from the backlog (§17)". A reader who follows §17 learns when the two
words apply and not what they do, which the reviewer raised and which is worth defining when v2's
development stage is written. Cheap to change: it is one clause in one paragraph, and this ticket
is gated besides, so it does not land without the human's word.

*Re-close round:* that last clause no longer holds. Under T0.21 a spec diff is not gated, so this
default lands with the self-merge rather than at a human's `merge` — which is what the addendum on
the task asked for, and the default stays one clause, cheap to change in a later ticket. The
round itself took one default of its own: the four greps' diff base is read as `origin/main`
rather than `main`, because this worktree's local `main` is the primary checkout's branch, one
merge behind, and is not the main the branch merges into. The ticket file's Addendum says so.
