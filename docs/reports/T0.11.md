## Defaults taken under §4

- **Review, not Decision, for the human step.** The ticket says the run stops. A Decision here
  would be answered by the skill on `main`, whose `branch.mjs` recreates `t0-11` off `main`; the
  work is safer at Review with the `setup` comment posted on the row. A developer surface, and
  nothing is lost either way.
- **Six comment kinds the ticket does not name** — `change`, `newWork`, `merged`, `applied`,
  `noted`, `setup`, and `resolved` after pass 3. The protocol needs one ⟡ comment on every
  assessed reply, or the next run reads it again; each shape gets a voice in `compose`, tested.
- **The word is the newest reply and begins it.** "merge", "Merge it", "apply, then carry on";
  not "don't merge yet", not "after you merge"; and "merge" followed by "wait" grants nothing.
  §4 says so.
- **`--merge` required, `--delete-branch` dropped.** A flagless merge takes the repository's
  setting the guard cannot see; a squash rewrites the hash `merge-detect` needs. gh's local
  branch delete fails while another worktree holds the branch and would read as a refusal.
- **The preflight reads the board over the API, or not at all.** Without the token no comments
  are read and the run says so; there is no connector fallback (AGENTS.md).
- **Pipeline comments still go through the connector.** The token reads; the prefix tells the
  voices apart, as §4 has always said. Open question 4.
- **The guard's hook timeout is 60 s** in `.claude/settings.json`, up from 10: two network calls
  at 4 s each fit under it with room.
- **`.env.migrate` stays out of `.worktreeinclude`** until the check is proven live, as the
  ticket's own condition reads. Open question 3.
- **An idle run files one Fix task only when step 0 itself went red** — a failed script, a gate
  that refused, a worktree that could not be removed — under E0.2 Pipeline. T0.10 open question
  11, closed.
- **The live check is step 0a**, ahead of the thread read; `claim.mjs` refuses a live marker.
