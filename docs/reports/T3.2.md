## Defaults taken

**The cycle is keyed to the newest *human-authored* version's section text, not to "(artifact
version, section, check)" as AA1's sentence reads.** The literal key does not terminate: the
author's own revisions are new versions of the section too, so every revision would reopen every
check the loop had just closed and §6's two-round cap — a product-spec law — would never bite.
AA1's own trigger sentence is "if the human later rewrites the section", and that is what shipped.
The section's text is hashed rather than the version id compared, so a human rewrite of *another*
section leaves this one's closure standing, which is what "a new version of that section" asks
for.

**A null baseline holds the closure rather than reopening it.** Rows 0015 wrote carry no baseline,
and a section no human version holds has none either. Unknown is not "different", and reopening on
it would re-spend two paid rounds on a guess.

**The trailing break run is dropped before a section is hashed.** The parse is lossless, so a
section carries the blank lines separating it from the next, and a section moved to the end of the
document loses one without a word of it changing. That is formatting at the seam — `spliceSection`
already treats it as such — and a baseline that moved on it would reopen every check on a section
somebody reordered.

**An over-long quote is cut and recorded as cut, as well as surfaced.** AA3 says to surface such an
objection; it does not say what to store, and `evidence` caps at 2000. A cut quote is no longer the
verbatim evidence §1 law 3 asks for, so it is stored cut, flagged `evidence_truncated`, and never
shown to the author — a revision argued from a fragment is a revision argued from something the
critic did not say.

**Within one artifact version, the newest run still wins.** §5's cache key carries the pack, its
version and the protocol version beside the artifact version, so one version can hold several runs
(AA2 does not say which). The last one is the current reading.
